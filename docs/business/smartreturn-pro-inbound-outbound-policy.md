# SmartReturn Pro 입고/출고 정책

이 문서는 SmartReturn Pro 신규 제작 기준이다. 기존 SmartReturn의 구현기록, 화면, DB, 입출고 처리 방식을 그대로 따르지 않는다.

## 입고 메뉴

- 입고자료 준비
- 입고검수 작업
- 입고확정
- 입고 이력조회

## 입고 원칙

- 입고는 예정입고와 무예정 입고를 모두 지원해야 한다.
- 무예정 입고도 확정 전 재고 반영을 금지한다.
- 입고 검수는 실제 입고 수량과 상품을 확인하는 작업이다.
- 입고 확정 전에는 `inventory_events`를 생성하지 않는다.
- 입고 confirm과 apply-inventory를 분리한다.
- 입고 확정 결과는 서버 업무 흐름에서 재고 이벤트로 반영한다.

## 입고자료 준비

- 예정입고 자료를 업로드하고 검증한다.
- 원본 row와 검증 오류를 보존한다.
- 자료 준비 화면에서 재고를 반영하지 않는다.

## 입고검수 작업

- 작업자는 상품, 바코드, 수량을 확인한다.
- 예정 자료가 있으면 비교하고, 무예정이면 별도 예외 흐름으로 처리한다.
- 스캔 이벤트는 `scan_events`에 남기되 재고 원장으로 취급하지 않는다.

## 입고확정

- 검수 완료 대상을 확정한다.
- 확정 시 서버에서 재고 이벤트를 생성한다.
- 확정 실패와 Local Agent 기능 실패를 분리한다.

## 출고 메뉴

- 출고자료 준비
- 출고검수 작업
- 출고확정
- 출고 이력조회

## 출고 원칙

- 출고 자료 준비와 출고 검수를 분리한다.
- 출고 스캔 중 재고 차감을 금지한다.
- 출고 완료/확정 시 서버 재고 이벤트를 생성한다.
- 재고 부족, 상품 불일치, 수량 불일치는 확정 전 예외로 표시한다.
- 웹 출고검수와 로컬 스캔 클라이언트의 역할을 분리한다.

## 웹 출고검수와 로컬 스캔 클라이언트

- 웹 출고검수는 업무 상태, 검수 결과, 확정 흐름을 관리한다.
- 로컬 스캔 클라이언트는 스캔 입력, 장치 제어, 프린터, 사운드 같은 현장 기능을 담당한다.
- 로컬 스캔 클라이언트는 재고를 직접 변경하지 않는다.
- 재고 변경은 서버 업무 확정 흐름에서만 발생한다.

## Codex 구현 전 체크

- 입고자료 준비, 입고검수, 입고확정이 분리되어 있는가?
- 무예정 입고가 확정 전 재고 반영되지 않는가?
- 입고 confirm과 apply-inventory가 분리되어 있는가?
- 출고 스캔 중 재고 차감을 하지 않는가?
- 출고 완료/확정 시 서버 재고 이벤트가 생성되는가?
- 웹 출고검수와 로컬 스캔 클라이언트 역할이 분리되어 있는가?
