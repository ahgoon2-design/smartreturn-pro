# SmartReturn Pro 기준정보 정책

이 문서는 SmartReturn Pro 신규 제작 기준이다. 기존 SmartReturn의 구현기록, 기준정보 구조, 화면 구성을 그대로 따르지 않는다.

## 기준정보 메뉴

- 고객사
- 상품
- 창고
- 공통코드
- 사용자/권한

## 고객사 기준

- 고객사는 3PL 업무의 기본 scope다.
- 모든 업무 데이터는 `client_id` 기준으로 분리한다.
- 고객사 상세에서 사용창고를 연결할 수 있어야 한다.
- 고객사별 사용 가능 창고, 사용 상태, 계약 상태를 관리한다.
- 고객사 삭제보다 사용중지를 우선한다.

## 창고 기준

- 창고는 업무 처리 위치와 재고 scope다.
- 고객사-창고 연결은 필수다.
- 창고 선택은 선택 고객사의 사용창고만 표시한다.
- 창고가 전체 공용이라도 고객사별 사용 여부는 별도로 관리한다.
- 창고 삭제보다 사용중지를 우선한다.

## 상품 기준

- 상품은 `client_id` 범위 안에서 관리한다.
- 상품코드는 고객사 범위에서 중복되지 않도록 기준을 둔다.
- 상품명, 규격, 대표 바코드, 상태, 기본 단위 정보를 관리한다.
- 바코드는 독립 메뉴보다 상품 상세 하위 정보로 관리한다.
- 상품 삭제보다 사용중지를 우선한다.

## 바코드 기준

- `products.barcode`는 대표 낱개 바코드다.
- `product_barcodes`는 추가, 박스, 카톤, 외부 바코드를 관리한다.
- `unit_qty`는 스캔 1회당 반영 수량이다.
- 바코드 매칭은 반드시 `client_id` 범위 안에서 수행한다.
- 하나의 바코드가 여러 상품에 연결될 수 있는지 여부는 고객사별 정책으로 명확히 정한다.

## 공통코드 기준

- 화면 하드코딩을 금지한다.
- 업무 상태, 택배사, 반품소스, 판정사유, 보류사유는 공통코드 또는 기준정보로 관리한다.
- 공통코드는 표시명, 코드값, 정렬순서, 사용여부를 가진다.
- 코드값은 영어 enum 형태를 유지할 수 있으나 설명과 운영 기준은 한글로 작성한다.

## 사용자/권한 기준

- 내부 운영자와 고객사 사용자는 `role` 기준으로 구분한다.
- `client_id` 유무로 사용자 성격을 판단하지 않는다.
- 내부 운영자는 고객사를 선택할 수 있다.
- 고객사 사용자는 자기 `client_id`로 고정된다.
- 권한 변경 이력은 추적 가능해야 한다.

## 사용중지 우선 원칙

- 기준정보는 삭제보다 사용중지를 우선한다.
- 이미 업무 데이터에서 사용된 기준정보는 삭제하지 않는다.
- 사용중지된 기준정보는 과거 이력 조회에는 표시하되 신규 입력에는 제한한다.

## Codex 구현 전 체크

- 기준정보가 `client_id` 또는 `warehouse_id` scope를 올바르게 따르는가?
- 고객사-창고 연결 기준이 반영되어 있는가?
- 창고 선택이 선택 고객사의 사용창고만 보여주는가?
- 바코드를 상품 상세 하위 정보로 다루는가?
- `products.barcode`, `product_barcodes`, `unit_qty`의 의미가 분리되어 있는가?
- 화면 하드코딩 코드값을 만들고 있지 않은가?
- 삭제보다 사용중지를 우선하는가?
