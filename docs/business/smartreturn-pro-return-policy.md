# SmartReturn Pro 반품 정책

이 문서는 SmartReturn Pro 신규 제작 기준이다. 기존 SmartReturn의 구현기록, 화면, DB, 반품 처리 방식을 그대로 따르지 않는다.

## 반품 업무의 위치

- 반품은 SmartReturn Pro의 핵심 업무다.
- 반품 업무는 자료 준비, 실제 처리, 마감, 반출, 추적을 분리한다.
- 반품 데이터는 `agency_id`, `client_id`, `client_unit_id`, `warehouse_id` scope를 반드시 따른다.
- 반품처리 최종 흐름과 화면 기준은 `docs/business/return-processing-workflow-ux-design.md`를 따른다.

## 반품 데이터의 의미

- 구글시트는 업체 반품접수/회신 채널이다.
- CJ/택배 엑셀은 반품예정 자료다.
- 반품처리는 실제 창고 스캔/판정 원장이다.
- 반품접수자료와 반품예정자료는 매칭될 수도 있고 안 될 수도 있다.
- 매칭은 필수 관문이 아니라 참고/정확도 보조 기능이다.
- 반품 예정자료의 상품정보는 후보/참고값이다.
- 실제 상품, 수량, 판정은 반품처리 작업에서 확정한다.

## 구글시트 원칙

- 구글시트는 반품처리 원장이 아니다.
- 현장 스캔 중 Google Sheets API를 직접 호출하지 않는다.
- 구글시트 동기화 실패가 현장 반품처리 저장 실패가 되면 안 된다.
- 구글시트 회신은 별도 동기화 또는 후처리 흐름에서 다룬다.

## 내부 반품입고예정 화면 원칙

- 내부 반품입고예정 화면에는 구글시트 동기화를 넣지 않는다.
- 내부 반품입고예정 화면에는 업체 반품접수를 넣지 않는다.
- 내부 반품입고예정 화면에는 판정을 넣지 않는다.
- 내부 반품입고예정 화면에는 재고처리를 넣지 않는다.
- 이 화면은 반품예정 자료 준비와 검증에 집중한다.

## RETURN 메뉴

- 반품자료 준비
- 반품처리 작업
- 반품 마감
- 반품 반출
- 반품 통합추적

## 반품자료 준비

- 구글시트 접수자료와 CJ/택배 엑셀 같은 예정자료를 준비한다.
- 원본 업로드, 검증, 매칭 후보 생성까지만 담당한다.
- 실제 판정과 재고 반영은 담당하지 않는다.

## 반품처리 작업

- 실제 창고 스캔과 판정을 수행한다.
- 스캔 결과와 후보 자료를 비교할 수 있지만 후보를 확정값으로 취급하지 않는다.
- 실제 상품, 수량, 판정, 보류 사유는 작업자가 확정한다.
- 세부항목 없는 반품도 반품처리 화면 안에서 상품 스캔/검색/선택으로 현장 처리 상품을 추가해 처리한다.
- 스캔 처리와 그리드 선택 처리를 모두 지원한다.
- 고객사별 판정표/체크리스트 기준을 우선하고, `warehouse_id`가 확정되지 않은 판정은 처리완료하지 않는다.
- 반품 판정 즉시 `current_inventory`를 변경하지 않는다. 재고는 일마감/반출 확정 후 반영한다.

## 반품처리 작업 화면에 넣지 말 것

- 구글시트 동기화
- 업로드 이력
- 기간별 배치조회
- 반출 묶음
- 마감 확정
- 재고 이벤트 상세

## 라벨 출력 원칙

- 라벨 출력 실패는 판정 저장 실패가 아니다.
- 라벨, 프린터, 사운드 같은 Local Agent 기능은 업무 저장과 분리한다.
- 라벨 재출력은 별도 재시도 흐름으로 처리한다.

## Codex 구현 전 체크

- 구글시트를 반품처리 원장처럼 사용하고 있지 않은가?
- CJ/택배 엑셀을 반품예정 자료로만 다루는가?
- 반품접수자료와 반품예정자료 매칭을 필수 관문으로 만들지 않았는가?
- 실제 상품/수량/판정이 반품처리 작업에서 확정되는가?
- 반품처리 작업 화면에 업로드 이력, 마감, 반출, 재고 이벤트 상세를 넣지 않았는가?
- 라벨 출력 실패와 판정 저장 실패를 분리했는가?
- 세부항목 없는 반품을 반품 자료 등록 화면으로만 돌려보내고 있지 않은가?
- 스캔 처리와 선택 처리를 모두 지원하는가?
- 창고 확정 전 처리완료를 막는가?
