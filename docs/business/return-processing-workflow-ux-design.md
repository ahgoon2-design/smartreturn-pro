# 반품처리 업무흐름 및 UX/UI 최종 설계

이 문서는 반품처리 구현 전 기준 문서다. 화면 구현 지시가 아니라 업무 흐름, UI 책임, 작업자 언어, 금지 패턴을 고정한다.

## 최종 업무흐름

### 1. 업체 반품 세부정보 등록/수집

- 엑셀 등록.
- 복붙 등록.
- 향후 API/자동수집.
- 구글시트는 업체 반품접수/회신 채널이며 반품처리 원장이 아니다.

### 2. CJ 반품 운송장 정보 등록/수집

- 반품접수, 수거, 배송완료 정보.
- `return_tracking_no`는 현장 스캔 기준이다.
- `original_tracking_no`는 보조 조회 기준이다.

### 3. 센터 입고/반품처리

```text
배송완료 반품 센터 도착
→ 운송장 스캔
→ 세부항목 있으면 기존 row 기준 처리
→ 세부항목 없으면 상품 스캔/검색/선택으로 현장 row 생성
→ 스캔 처리 + 그리드 선택 처리 둘 다 지원
→ 상품/구성품/사은품 확인
→ 고객사별 판정
→ 판정별 창고 확정
→ 사진/영상 선택 증빙
→ 처리완료
```

### 4. 일마감

- 처리완료 자료 모음.
- 고객사별, 창고별, 판정별, 상품별 수량 확인.
- 일마감 확정.
- 일마감 후 재고반영.

### 5. 월마감/후속처리

- 제조사반출.
- 폐기.
- 부품적출.
- 보류 회신 처리.
- 파레트/박스 반출.
- 월마감 리포트/정산 기초자료.

## 확정 원칙

- 반품 판정 즉시 `current_inventory` 변경 금지.
- `warehouse_id` 없으면 처리완료 금지.
- 세부항목 없는 반품도 반품처리 화면 안에서 처리한다.
- 스캔 처리와 그리드 선택 처리를 둘 다 지원한다.
- 고객사별 판정 설정 기준으로 판정 버튼을 표시한다.
- 사진/영상은 증빙/분쟁 대응용이며 고객사 설정에 따라 필수 가능하다.
- 상품마스터에 없는 상품은 정상 처리완료하지 않는다.

## 반품처리 UX/UI 영역

### 상단 고정 영역

- 화면 제목: 반품 처리.
- 운송장 스캔/조회.
- 고객사/운영단위/처리모드/현재상태 요약.

### 중앙 좌측

- 상품 추가.
- 상품 스캔/검색/선택.
- 세부항목 없음이면 여기서 현장 상품 추가.

### 중앙 메인

- 처리 대상 상품 그리드.
- 세부항목 있으면 조회 row.
- 세부항목 없으면 추가된 상품 row.
- 처리상태, 수량, 판정, 창고 표시.

### 우측 또는 하단

- 선택 상품 상세.
- 수량.
- 고객사별 판정.
- 창고 자동배정/선택.
- 메모/사진.
- 기존 AI도우미 안에 판정 도움.

### 하단 액션

- 선택 처리.
- 보류.
- 처리완료.
- 초기화.

## 작업자 경험 문장

```text
운송장 찍는다.
상품 확인한다.
판정한다.
창고 확인한다.
처리완료 누른다.
```

## 문구 규칙

작업자 화면에는 내부 enum, DB 필드명, 개발자 용어를 노출하지 않는다.

| 내부 표현 | 작업자 표현 |
| --- | --- |
| `NO_DETAIL_MANUAL_INTAKE` | 현장 수동 처리 |
| `row 생성` | 상품 추가 |
| `return_tracking_no` | 반품 운송장번호 |
| `original_tracking_no` | 원운송장번호 |
| `GRID_SELECT` | 선택 처리 |
| `SCAN` | 스캔 처리 |

## 안내문 규칙

- 같은 의미의 안내문은 한 화면에 1회만 표시한다.
- 노란 안내 카드는 닫기/접기 가능해야 한다.
- 안내문은 사용자가 다음에 무엇을 해야 하는지 짧게 말해야 한다.
- 일반 카드/노란 안내 카드는 sticky로 고정하지 않는다.

## sticky 규칙

고정 가능:

- 앱 헤더.
- 작업 탭.
- 화면 제목.
- 핵심 작업바.
- 반품처리의 운송장 스캔 입력.

고정하지 말 것:

- 노란 안내 카드.
- 일반 카드.
- 긴 설명문.
- 그리드 상세 카드.

CSS 계층 방향:

```text
app header > work tabs > page header > grid header > card/content
```

1366x768 기준으로 sticky 영역이 그리드를 과하게 밀지 않게 한다.

## Codex 구현 전 체크

- 세부항목 없는 반품이 현재 화면에서 상품 추가/판정/처리완료까지 이어지는가?
- 스캔만 강제하지 않고 선택 처리도 가능한가?
- 창고 확정 전 처리완료가 차단되는가?
- 판정 즉시 현재고를 변경하지 않는가?
- 내부 enum이나 DB 필드명이 작업자 화면에 보이지 않는가?
- 노란 안내 카드가 화면을 계속 밀어내지 않는가?
