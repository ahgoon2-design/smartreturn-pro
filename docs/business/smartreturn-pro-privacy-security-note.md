주의: 이 문서는 법률 자문이 아니라 플랫폼 설계 참고자료다. 실제 계약·약관·개인정보처리방침 작성 전에는 최신 법령과 전문가 검토가 필요하다.

## 1. 문서 목적

SmartReturn Pro는 반품처리 플랫폼이므로 고객사, 대리점, 처리센터, 플랫폼 운영자가 함께 개인정보와 반품 데이터를 처리한다.

반품 처리 과정에는 주문자/수취인 정보, 주소, 전화번호, 송장번호, 반품 사유, 사진, 영상, 검수 기록, 작업 로그가 포함될 수 있다. 따라서 개인정보보호는 나중에 붙이는 부가기능이 아니라 플랫폼 기본 구조에 포함되어야 한다.

이 문서는 SmartReturn Pro 개발과 사업 운영에서 반드시 고려해야 할 개인정보보호·보안 설계 기준을 정리한다.

## 2. SmartReturn Pro에서 개인정보로 봐야 할 항목

SmartReturn Pro에서 개인정보 또는 개인정보성 데이터로 취급해야 할 항목은 다음과 같다.

| 구분 | 예시 |
|---|---|
| 주문/반품 정보 | 주문자 이름, 수취인 이름, 전화번호, 주소, 주문번호, 송장번호 |
| 고객 문의 정보 | 반품 사유, 요청사항, 상담 메모 |
| 계정 정보 | 고객사 담당자 계정, 대리점 계정, 센터 작업자 계정, 관리자 계정 |
| 작업 로그 | 로그인 기록, 접속 IP, 작업자 ID, 조회/수정/삭제/확정 이력 |
| 증빙 파일 | 상품 사진, 박스 사진, 라벨 사진, 검수 영상 |
| 운영 정보 | 권한 변경 이력, 다운로드 이력, 원본 조회 이력 |

특히 사진과 영상은 상품 증빙처럼 보이더라도 택배 라벨, 이름, 전화번호, 주소가 찍히면 개인정보 파일로 취급해야 한다.

## 3. 적용해야 할 주요 법·제도 축

SmartReturn Pro에서 참고해야 할 주요 법·제도 축은 다음과 같다.

| 구분 | 플랫폼 적용 의미 |
|---|---|
| 개인정보 보호법 제29조 안전조치의무 | 개인정보가 유출·분실·도난·위조·변조·훼손되지 않도록 기술적·관리적·물리적 보호조치 필요 |
| 개인정보 보호법 제26조 업무위탁 | 고객사·대리점·처리센터·클라우드 간 위탁/재위탁 구조 정리 필요 |
| 개인정보 보호법 제30조 개인정보 처리방침 | 수집 항목, 목적, 보유기간, 파기, 위탁, 권리행사 방법 등 공개 필요 |
| 개인정보의 안전성 확보조치 기준 | 접근권한 관리, 접속기록 보관, 암호화, 악성프로그램 방지, 물리적 보호 등 기준 |
| 유출 신고·통지 체계 | 일정 요건의 개인정보 유출 시 신고·통지 대응 루틴 필요 |
| ISMS-P | 초기 의무가 아닐 수 있으나 대형 고객사·공공·대기업 거래 시 기준으로 참고 필요 |

## 4. SmartReturn Pro 보안 설계 핵심 원칙

SmartReturn Pro의 보안 설계 원칙은 다음과 같이 고정한다.

```text
1. 개인정보는 최소 수집한다.
2. 고객사/대리점/처리센터 데이터는 백엔드 API에서 강제 차단한다.
3. 사진/영상은 개인정보 파일로 취급한다.
4. 모든 조회/다운로드/수정/삭제/확정은 로그를 남긴다.
5. 이름/전화번호/주소는 기본 마스킹한다.
6. 원본 확인은 권한 + 사유 + 로그가 필요하다.
7. 보관기간 종료 후 삭제할 수 있어야 한다.
8. 고객사·대리점·센터·클라우드는 위수탁 구조로 정리한다.
9. 유출 의심 시 72시간 신고 여부 판단 루틴을 둔다.
10. ISMS-P 의무 전이라도 그 수준을 목표로 설계한다.
```

## 5. 테넌트·데이터 범위 격리

SmartReturn Pro의 기본 데이터 계층은 다음 구조를 따른다.

```text
platform_owner
  → agency_id
  → client_id
  → client_unit_id
  → warehouse_id
```

반품처리에서는 고객 소유권과 처리 담당을 분리해야 한다.

| 필드 | 의미 |
|---|---|
| `owner_agency_id` | 고객사를 소유·관리하는 대리점 |
| `processing_agency_id` | 실제 반품 업무를 처리하는 주체 |
| `client_id` | 고객사 |
| `client_unit_id` | 고객사 하위 단위 |
| `warehouse_id` | 실제 재고·입고·처리 장소 |

백엔드 API는 반드시 다음을 강제해야 한다.

```text
- 고객사는 자기 반품건만 조회
- 대리점은 자기 고객사와 처리 의뢰 건만 조회
- 처리센터는 배정된 처리 건만 조회
- 동현/플랫폼 운영자는 권한 있는 범위만 조회
- owner_agency_id와 processing_agency_id를 혼동하지 않음
- 프론트 버튼 숨김만으로 권한 차단하지 않음
```

## 6. 권한 구조

SmartReturn Pro 권한은 세 가지로 분리한다.

### 6.1 역할 권한

예시:

```text
- SUPER_ADMIN
- PLATFORM_ADMIN
- AGENCY_ADMIN
- CLIENT_ADMIN
- CENTER_MANAGER
- CENTER_WORKER
- READONLY_AUDITOR
```

### 6.2 데이터 범위 권한

```text
- 어느 agency_id까지 볼 수 있는가
- 어느 client_id까지 볼 수 있는가
- 어느 client_unit_id까지 볼 수 있는가
- 어느 warehouse_id까지 볼 수 있는가
- owner_agency_id 기준 조회인가
- processing_agency_id 기준 조회인가
```

### 6.3 기능 권한

권한 체크표 열 순서는 다음으로 고정한다.

```text
조회 / 등록 / 수정 / 삭제 / 처리 / 확정 / 관리
```

개인정보 관련 기능은 별도 권한으로 분리하는 것이 안전하다.

```text
- 개인정보 원문 보기
- 주소 전체 보기
- 전화번호 전체 보기
- 사진/영상 원본 보기
- 원본 다운로드
- 대량 다운로드
- 개인정보 삭제/파기
- 권한 변경
```

## 7. 접속기록·작업로그

SmartReturn Pro는 개인정보 접근·처리 기록을 반드시 남겨야 한다.

필수 로그 항목:

```text
- 사용자 ID
- 역할
- 접속 일시
- IP 주소
- 기기/브라우저 정보
- 대상 고객사/client_id
- 대상 반품건/return_case_id
- 수행 작업: 조회, 등록, 수정, 삭제, 처리, 확정, 다운로드
- 사진/영상 원본 조회 여부
- 대량 다운로드 여부
- 권한 변경 여부
- 작업 성공/실패 여부
```

보관 원칙:

```text
- 접속기록은 최소 1년 이상 보관을 기본 기준으로 잡는다.
- 권한 부여/변경/말소 이력은 장기 보관 대상으로 본다.
- 대형 고객사 또는 대량 개인정보 처리 시 2년 이상 보관도 검토한다.
- 로그는 일반 사용자 또는 현장 작업자가 수정/삭제할 수 없어야 한다.
```

## 8. 암호화·마스킹·원문 보기

### 8.1 비밀번호와 인증

```text
- 비밀번호는 평문 저장 금지
- bcrypt/argon2 등 단방향 해시 사용
- 기본 개발용 secret 운영환경 사용 금지
- access token / refresh token 분리
- 토큰 만료와 강제 폐기 루틴 필요
```

### 8.2 화면 마스킹

기본 화면에서는 다음처럼 마스킹한다.

| 항목 | 기본 표시 예시 |
|---|---|
| 이름 | 홍*동 |
| 전화번호 | 010-****-1234 |
| 주소 | 서울시 강남구 **** |
| 송장번호 | 일부 마스킹 또는 권한별 표시 |
| 주문번호 | 고객사 정책에 따라 일부 마스킹 |

원문 보기는 다음 조건을 둔다.

```text
- 원문 보기 권한 필요
- 원문 보기 사유 입력
- 원문 보기 로그 기록
- 대량 원문 조회 제한
- 관리자도 기본은 마스킹
```

## 9. 사진·영상 파일 보안

SmartReturn Pro에서 사진/영상은 가장 위험한 개인정보 저장소가 될 수 있다.

### 9.1 저장 원칙

```text
- Object Storage 버킷 public 금지
- 파일 직접 URL 공개 금지
- signed URL 또는 일회성 접근 URL 사용
- URL 만료시간 짧게 설정
- 원본/썸네일 분리
- 원본 접근 권한 별도 관리
- 원본 다운로드 로그 기록
```

### 9.2 업로드 정책

```text
- 사진은 선택 등록 가능
- 어떤 판정에서도 사진 필수 강제 금지
- 영상은 무제한 허용 금지
- 영상 1개당 최대 용량 제한
- 반품 1건당 파일 개수 제한
- 업로드 파일 확장자/MIME 타입 검증
- 악성 파일 검사 검토
```

### 9.3 보관 정책

```text
- 최근 3개월: Object Storage
- 이후: Archive Storage 검토
- 계약/법적 보관기간 종료 후 삭제
- 고객사별 보관기간 설정
- 삭제 대상 파일과 DB 메타데이터 정합성 유지
```

## 10. 개인정보 처리 위탁 구조

SmartReturn Pro는 고객사, 대리점, 처리센터, 클라우드 사업자가 얽힌 구조다.

예상 역할은 다음과 같다.

| 주체 | 역할 |
|---|---|
| 고객사 | 반품 고객 개인정보의 원 수집·이용 주체 |
| SmartReturn Pro 운영사 | 플랫폼 제공자, 수탁자 또는 일부 개인정보처리자 |
| 대리점 | 고객사 반품업무 처리 수탁자 또는 재수탁자 |
| 처리센터 | 실제 입고/검수 처리 수탁자 또는 재수탁자 |
| 클라우드 사업자 | 인프라 수탁자 |

계약서 또는 위수탁 문서에 포함할 항목:

```text
- 위탁업무의 목적과 범위
- 처리하는 개인정보 항목
- 처리 목적 외 사용 금지
- 재위탁 제한 또는 재위탁 승인 절차
- 개인정보 접근권한 관리
- 안전성 확보조치
- 보관기간과 삭제 기준
- 사진/영상 원본 보관 기준
- 유출 시 통보 절차
- 손해배상 및 책임 범위
- 위탁 종료 시 자료 반납/삭제/파기
- 수탁자 관리·감독 방법
```

SmartReturn Pro 서비스 운영 시 개인정보처리방침에는 최소한 다음 항목이 필요하다.

```text
- 개인정보 처리업무 위탁 현황
- 정보주체 권리 행사 방법
- 개인정보 보호책임자
- 접속기록 보관
- 사진/영상 보관 및 삭제 정책
- 클라우드 저장 위치와 관리 기준
- 유출 사고 대응 절차
```

## 12. 유출 사고 대응 루틴

개인정보 유출이 의심되면 아래 루틴을 따른다.

```text
1. 유출 의심 감지
2. 관련 계정·토큰 긴급 잠금
3. 접근 로그 보존
4. 영향 고객사/대리점/처리센터 식별
5. 유출 가능 개인정보 항목 산정
6. 외부 접근 여부 확인
7. 신고·통지 대상 여부 판단
8. 필요 시 72시간 내 신고 체계 가동
9. 고객사 통보
10. 재발방지 조치
11. 사고 보고서 작성
```

플랫폼에는 사고 대응을 위한 관리자 기능 또는 운영 절차가 필요하다.

## 13. ISMS-P 기준 적용 방향

초기 SmartReturn Pro가 소규모로 시작하면 ISMS-P 인증 의무 대상이 아닐 수 있다. 다만 다음 경우에는 ISMS-P 또는 그에 준하는 보안체계가 필요해질 수 있다.

```text
- 대형 고객사 계약
- 공공·대기업 고객사 계약
- 대량 개인정보 처리
- 고객 포털 확대
- 처리센터/대리점 전국 확장
- 클라우드 인프라 외부 심사
```

초기부터 ISMS-P 기준을 참고해 설계하면 나중에 보안 체계를 다시 만드는 비용을 줄일 수 있다.

## 14. SmartReturn Pro 구현 우선순위

개발 우선순위는 다음과 같다.

### 1순위: 백엔드 데이터 범위 차단

```text
- agency_id
- client_id
- client_unit_id
- warehouse_id
- owner_agency_id
- processing_agency_id
```

### 2순위: 개인정보 마스킹

```text
- 이름
- 전화번호
- 주소
- 송장번호
- 사진/영상 원본
```

### 3순위: 접속/작업 로그

```text
- 조회
- 등록
- 수정
- 삭제
- 처리
- 확정
- 다운로드
- 권한 변경
```

### 4순위: 사진/영상 저장소 보안

```text
- public 금지
- signed URL
- 원본/썸네일 분리
- 보관기간
- Archive
- 삭제 루틴
```

## 17. 최종 판단

SmartReturn Pro에서 개인정보보호는 나중에 붙이는 기능이 아니라 플랫폼 기본 골격이다.

가장 위험한 구멍은 다음과 같다.

```text
- 고객사 A가 고객사 B 반품건을 보는 것
- 대리점이 다른 대리점 고객정보를 보는 것
- 처리센터가 배정되지 않은 반품건을 보는 것
- 사진/영상 원본 URL이 외부에 노출되는 것
- 관리자/작업자 개인정보 조회 로그가 없는 것
- 고객사 자료를 오래 보관하고도 삭제 기준이 없는 것
```

따라서 SmartReturn Pro는 다음 기준으로 설계한다.

```text
백엔드 권한 강제
+ 데이터 범위 격리
+ 개인정보 마스킹
+ 사진/영상 private 저장
+ 접속/작업 로그
+ 위수탁 계약 구조
+ 보관/삭제 정책
+ 유출 대응 루틴
```
