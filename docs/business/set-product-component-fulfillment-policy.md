# 세트상품/구성품/사은품/합포장 정책

SmartReturn은 제조/생산 BOM 플랫폼이 아니다. SmartReturn의 세트·구성품 관리는 이커머스 풀필먼트 운영 기준이다.

핵심 문장:

```text
세트상품은 주문/판매 단위이고, 구성품은 피킹/검수/재고 단위다.
```

현장 작업자 화면에는 BOM이라는 용어를 과다 노출하지 않는다. 화면에는 “세트/구성품”, “사은품”, “합포장” 중심으로 표시한다.

## 금지 방향

- 제조 BOM 중심 설계 금지.
- 생산투입/생산입고 중심 금지.
- 원재료 소요량 중심 금지.
- 생산 원가 계산 플랫폼처럼 확장 금지.

## 포함 대상

- 세트상품.
- 합포장.
- 사은품.
- 이벤트 구성품.
- 교환출고 보충 구성품.
- 반품 구성품 확인.
- 부품적출 가능 구성품.

## 상품 유형 후보

- `SINGLE`: 단품.
- `SET`: 세트 대표상품.
- `COMPONENT`: 구성품.
- `GIFT`: 사은품.
- `PART`: 적출 부품/수리 부품.

enum 값은 내부 저장값으로 사용할 수 있지만, 작업자 화면에는 필요한 경우 한글 표시명을 사용한다.

## 출고에서의 사용

예시:

```text
판매상품: 쿠팡 조리도구 4종 선물세트
구성품:
- 조리도구 A 1개
- 조리도구 B 1개
- 조리도구 C 1개
- 조리도구 D 1개
```

주문:

```text
쿠팡 조리도구 4종 선물세트 10개
```

시스템 전개:

```text
조리도구 A 10개 필요
조리도구 B 10개 필요
조리도구 C 10개 필요
조리도구 D 10개 필요
```

출고 흐름:

```text
구성품 피킹
→ 구성품 검수
→ 세트 포장
→ 출고검수 완료
→ 구성품 재고 차감
```

초기 구현은 주문 시 조립형 세트를 우선해도 된다. 단, 사전 조립형 세트로 확장 가능하게 설계한다.

## 사은품/합포장 예시

```text
본상품 1개
+ 샘플 파우치 2개
+ 쇼핑백 1개
→ 같이 피킹/검수/포장
→ 사은품 재고도 차감 가능
```

사은품은 프로모션 조건, 고객사 정책, 기간, 채널에 따라 달라질 수 있다. 사은품 누락은 출고 클레임과 반품 판정에 영향을 줄 수 있다.

## 반품에서의 사용

세트상품 반품은 구성품 체크리스트를 자동 표시한다.

```text
조리도구 A 정상
조리도구 B 정상
조리도구 C 누락
조리도구 D 파손
사은품 쇼핑백 미회수
```

판정 영향 예시:

- 필수 구성품 모두 있음 + 상품 정상: 양품 가능.
- 필수 구성품 누락: 양품 불가, 리퍼/보류/구성품누락 추천.
- 본체 파손 + 일부 구성품 정상: 부품적출 추천.
- 사은품 미회수: 고객사 정책에 따라 보류 또는 감액/메모 처리.

## 화면 위치

```text
상품 관리
→ 상품 상세
→ 세트·구성품 탭
```

작업자 화면에는 복잡한 내부 구조를 보여주지 않는다. 작업자 원칙은 다음과 같다.

```text
스캔한다.
보이는 대로 확인한다.
이상 있으면 체크한다.
완료 누른다.
```

시스템은 세트 여부, 구성품 필요수량, 누락/초과, 사은품 회수 여부, 판정 영향 안내를 자동으로 계산해야 한다.

## Codex 구현 전 체크

- 제조 BOM이나 생산 투입 구조로 과대 설계하고 있지 않은가?
- 세트 대표상품과 구성품의 재고 단위가 분리되는가?
- 사은품과 합포장을 별도 정책으로 고려하는가?
- 반품 시 구성품/사은품 누락이 판정 추천에 반영되는가?
- 작업자 화면에 BOM 같은 내부 용어를 과다 노출하지 않는가?
