## A. 외부 공개 후보 본문

### 1. 총칙

SmartReturn-platform은 반품 접수, 택배 수거·배송조회, 센터 입고, 검수·판정, 사진·첨부파일 관리, 재고 반영, 폐기·제조사반품·외부반출, 고객 문의, 사고·분쟁 처리, 정산, 관리자 계정 관리, 감사로그·보안로그 관리를 지원하는 물류 운영 플랫폼이다.

SmartReturn-platform은 개인정보 보호법 등 관계 법령을 준수하며, 서비스 제공에 필요한 범위에서 개인정보를 처리한다. 운송장번호, 이름, 연락처, 주소, 이메일, 반품 접수 정보, 상품명/옵션/수량, 상품 상태 판정 결과, 사진 또는 첨부파일, 접속 로그, 처리 이력은 단독 또는 다른 정보와 결합하여 개인을 식별할 수 있는 정보로 관리한다.

### 2. 개인정보의 처리 목적

SmartReturn-platform은 다음 목적을 위해 개인정보를 처리한다.

| 처리 목적 | 주요 내용 |
| --- | --- |
| 반품 접수 및 처리 | 반품 요청 확인, 고객사·주문·상품·운송장 매칭, 접수 상태 관리 |
| 택배 수거·배송조회 | 수거 요청, 운송 상태 조회, 운송장 기반 사고 확인 |
| 센터 입고·검수·판정 | 입고 스캔, 상품·수량 확인, 상태 판정, 처리완료 |
| 사진·첨부파일 관리 | 파손, 오배송, 분쟁, 판정 근거 자료 관리 |
| 재고·반출·폐기 처리 | 마감 이후 재고 반영, 폐기, 제조사반품, 외부반출 이력 관리 |
| 고객 문의·사고·분쟁 처리 | 문의 접수, 처리 안내, 이의 제기, 사고·분쟁 대응 |
| 정산 | 고객사, 대리점, 센터 단위 작업량 집계와 청구·검수 자료 작성 |
| 관리자 계정·권한 관리 | 사용자 인증, 권한 부여, 계정 상태 관리, 비정상 접근 차단 |
| 감사로그·보안로그 관리 | 개인정보 접근 이력, 다운로드 이력, 권한 변경 이력, 보안 사고 대응 |
| 알림 발송 | 반품 상태, 입고, 판정, 배송 상태, 공지 안내 |
| 외부 API 연동 | 반품 접수자료 수집, 택배 수거·배송 상태 조회, 연동 오류 처리 |

### 3. 처리하는 개인정보 항목

SmartReturn-platform은 다음 개인정보를 처리할 수 있다.

| 구분 | 처리 항목 |
| --- | --- |
| 최종 고객/수취인 정보 | 이름, 연락처, 주소, 이메일, 운송장번호, 반품 접수 정보, 상품명/옵션/수량, 반품 사유, 배송 상태 |
| 반품 처리 정보 | 센터 입고 이력, 상품 스캔 이력, 검수 결과, 판정 결과, 처리 담당자, 처리 시각, 메모 |
| 사진·첨부파일 정보 | 반품 상품 사진, 포장 상태 사진, 파손 증빙, 문의 첨부파일, 등록자, 등록 시각 |
| 고객사·대리점·센터 정보 | 고객사명, 대리점/센터 정보, 담당자 계정, 소속, 역할, 권한 |
| 정산 관련 정보 | 처리 건수, 판정·마감·반출 이력, 정산 기준, 사고·분쟁 증빙 |
| 관리자 계정 정보 | 계정 ID, 이름, 소속, 역할, 이메일, 휴대폰번호, 계정 상태 |
| 접속·감사로그 | 접속 일시, IP 주소, 브라우저 정보, 요청 이력, 권한 변경 이력, 다운로드 이력 |
| 외부 API 연동 정보 | 운송장번호, 외부 접수 식별자, API 요청·응답 식별자, 연동 상태, 오류 이력 |

SmartReturn-platform은 주민등록번호, 민감정보, 서비스 제공에 불필요한 개인통관고유부호를 기본 수집 항목으로 두지 않는다. 개인통관고유부호가 해외 반품, 수입 통관, 법령상 신고 등 별도 업무에 필요한 경우에는 별도 절차와 보호조치를 적용한다.

### 4. 개인정보 수집 방법

SmartReturn-platform은 다음 방법으로 개인정보를 수집하거나 제공받을 수 있다.

- 고객사 또는 쇼핑몰 담당자의 반품 접수자료 업로드, API, 웹훅, 수동 입력
- 택배 수거·배송조회 API, 운송장 기반 상태 조회
- 센터 입고 스캔, 상품 스캔, 판정 입력, 사진·첨부파일 등록
- 고객 문의, 사고·분쟁 접수, 고객사 회신 자료
- 관리자 계정 생성, 로그인, 권한 변경, 다운로드, 감사로그·보안로그
- 정산 마감, 반출 확정, 재고 이벤트 생성 과정에서 발생한 업무 이력

### 5. 개인정보의 보유 및 이용 기간

SmartReturn-platform은 개인정보를 처리 목적 달성 시까지 보유·이용하며, 관계 법령에 따른 보존 의무, 계약 이행, 정산, 사고·분쟁 대응, 감사 목적이 있는 경우 해당 범위에서 보관한다.

| 정보 유형 | 보유 기준 |
| --- | --- |
| 반품 접수·처리 정보 | 반품 처리 목적 달성 및 계약상 업무 수행에 필요한 기간 |
| 운송장번호와 배송조회 이력 | 수거·배송조회, 사고 확인, 분쟁 대응에 필요한 기간 |
| 사진·첨부파일 | 판정, 고객사 회신, 사고·분쟁 대응에 필요한 기간 |
| 정산 정보 | 정산, 청구, 세무, 계약, 분쟁 대응에 필요한 기간 |
| 계정 정보 | 계정 이용 기간과 권한 관리에 필요한 기간 |
| 접속로그·감사로그 | 보안, 권한 감사, 침해사고 대응에 필요한 기간 |
| API 원본 이벤트와 오류 이력 | 중복 처리 방지, 장애 추적, 연동 오류 대응에 필요한 기간 |

### 6. 개인정보의 파기 절차 및 방법

SmartReturn-platform은 보유기간 경과, 처리 목적 달성, 계약 종료, 정보주체의 적법한 요청 등으로 개인정보가 불필요하게 된 경우 정해진 절차에 따라 파기한다.

- 전자 파일: 복구 또는 재생이 어렵도록 안전한 방식으로 삭제한다.
- 데이터베이스 정보: 업무 원장 정합성, 법정 보존, 정산·분쟁 대응 필요성을 확인한 뒤 삭제, 분리 보관 또는 비식별 처리한다.
- 사진·첨부파일·업로드 원본·export 파일: 파일 저장소의 실제 객체와 메타데이터를 함께 관리한다.
- 백업 데이터: 백업 보관 주기와 복구 정책에 따라 접근을 제한하고 정해진 주기에 삭제한다.
- 출력물: 분쇄, 파쇄, 소각 등 재생이 어려운 방법으로 폐기한다.

### 7. 개인정보의 제3자 제공

SmartReturn-platform은 개인정보를 수집·이용 목적 범위에서 처리하며, 정보주체 동의, 법령상 근거, 계약상 필요, 사고·분쟁 대응 등 정당한 사유가 있는 경우를 제외하고 제3자에게 제공하지 않는다.

서비스 제공 과정에서 외부 기관이 자기 목적을 위해 개인정보를 제공받는 경우에는 제공받는 자, 제공 목적, 제공 항목, 보유 및 이용 기간을 별도로 안내한다.

### 8. 개인정보 처리업무의 위탁

SmartReturn-platform은 서비스 제공을 위해 알림 발송, 클라우드 인프라 운영, 서버·데이터베이스·로그 보관, 고객지원, 파일 저장, 택배 수거·배송조회 연동 등 일부 업무를 외부 업체에 위탁할 수 있다.

위탁 업무가 발생하는 경우 수탁자, 위탁업무, 처리 항목, 보유 및 이용 기간, 재위탁 여부, 안전성 확보조치를 공개하고 수탁자를 관리·감독한다.

### 9. 개인정보의 국외 이전 여부

SmartReturn-platform은 개인정보의 저장 위치, 처리 도구, 알림 발송, 로그·모니터링, 고객지원, 외부 API 연동 구조에 따라 국외 이전 여부를 관리한다.

개인정보의 국외 이전이 발생하는 경우 이전받는 자, 이전 국가, 이전 일시와 방법, 이전 항목, 이용 목적, 보유 및 이용 기간, 거부 방법과 거부 시 영향을 안내한다.

### 10. 정보주체와 법정대리인의 권리·의무 및 행사 방법

정보주체는 SmartReturn-platform이 처리하는 개인정보에 대해 열람, 정정, 삭제, 처리정지, 동의 철회 등을 요구할 수 있다. SmartReturn-platform은 본인 확인, 요청 범위 확인, 법령상 보존 필요성, 정산·분쟁·사고 증빙 보존 필요성을 확인한 뒤 요청을 처리한다.

권리 행사는 고객사, 대리점, 센터, 플랫폼 운영자 중 실제 개인정보 처리 책임과 계약 구조에 맞는 접수 창구를 통해 처리한다.

### 11. 개인정보의 안전성 확보조치

SmartReturn-platform은 개인정보 보호를 위해 다음 조치를 적용한다.

- 역할별 접근권한 관리와 최소권한 원칙 적용
- 고객사, 대리점, 센터, 창고 단위 권한·테넌시 격리
- 개인정보 전송 구간 암호화와 저장 구간 보호
- 비밀번호 단방향 암호화와 인증 정보의 평문 저장 금지
- 이름, 연락처, 주소, 이메일, 운송장번호, 사진·첨부파일에 대한 마스킹과 접근 제한
- 개인정보 상세조회, 수정, 삭제, 다운로드, 대량조회, 외부반출에 대한 권한 확인과 감사로그 기록
- 엑셀 다운로드와 export 파일의 생성자, 생성 시각, 조회 조건, 다운로드 이력 관리
- 첨부파일 접근 제한과 만료 링크 또는 인증된 다운로드 경로 적용
- API 키, 토큰, 시크릿의 암호화·접근 제한·노출 방지
- 로그 위변조 방지, 보안 이벤트 기록, 침해사고 대응 절차 운영
- 계정 비활성화, 퇴사자 권한 회수, 접근권한 정기 점검
- 테스트 데이터 비식별화와 실제 개인정보의 개발·테스트 환경 사용 제한

### 12. 개인정보 자동 수집 장치의 설치·운영 및 거부

SmartReturn-platform은 로그인 유지, 보안 세션 관리, 화면 상태 저장, 부정 접근 탐지, 서비스 안정성 분석을 위해 쿠키 또는 유사한 자동 수집 장치를 사용할 수 있다.

자동 수집될 수 있는 정보는 세션 식별자, 접속 일시, IP 주소, 브라우저 정보, 기기 정보, 요청 URL, 오류 로그, 사용 이력 등이다. 쿠키에는 이름, 연락처, 주소, 운송장번호 등 직접 식별 개인정보를 저장하지 않는 것을 원칙으로 한다.

### 13. 행태정보 처리 여부

SmartReturn-platform은 맞춤형 광고 목적의 행태정보를 기본 처리 항목으로 두지 않는다. 서비스 안정성, 보안 탐지, 사용성 개선을 위해 서비스 이용 로그를 처리하는 경우에는 처리 목적, 항목, 보유기간, 거부 방법을 안내한다.

### 14. 가명정보 처리 여부

SmartReturn-platform은 통계 작성, 서비스 품질 개선, 물류 효율 분석, 판정 기준 개선 등을 위해 가명정보를 처리할 수 있다. 가명정보를 처리하는 경우 처리 목적, 항목, 보유기간, 제3자 제공 여부, 재식별 금지, 분리 보관, 접근권한 제한을 적용한다.

### 15. 14세 미만 아동의 개인정보 처리 여부

SmartReturn-platform은 원칙적으로 14세 미만 아동을 대상으로 직접 회원가입 또는 서비스를 제공하지 않는다. 반품 접수자료에 14세 미만 아동의 개인정보가 포함되는 경우 관계 법령과 계약 구조에 따라 처리한다.

### 21. 권한·테넌시 격리 원칙

- 🔴 고객사 간 개인정보 상호 열람을 금지한다.
- 🔴 대리점은 자기 관할 범위 내 고객사, 센터, 정산 정보만 접근한다.
- 🔴 직영센터는 배정된 반품 처리 범위 내 정보만 접근한다.
- 🟠 플랫폼 운영자는 장애 대응, 보안, 고객지원, 정산 등 필요한 업무 범위에서만 접근한다.
- 🔴 백엔드 권한·테넌시 격리가 화면 표시보다 우선한다.
- 🔴 엑셀 다운로드, 대량조회, 외부반출은 별도 권한과 감사로그를 요구한다.
- 🔴 개인정보 조회, 수정, 삭제, 다운로드는 감사로그 대상이다.
- 🟡 주소, 연락처, 운송장번호, 이메일, 사진/첨부파일은 역할과 업무 목적에 따라 마스킹한다.
- 🟡 다운로드 사유 입력, 승인, 만료 링크, 재다운로드 제한, 워터마크 적용 기준을 정한다.

### 27. 개인정보 보호 구현 체크리스트

- [ ] 역할별 접근권한을 정의하고 API에서 재검증한다.
- [ ] 고객사, 대리점, 센터, 창고 기준 테넌시 격리를 적용한다.
- [ ] 이름, 연락처, 주소, 이메일, 운송장번호, 사진/첨부파일 마스킹 기준을 적용한다.
- [ ] 상세조회 권한을 목록조회 권한과 별도로 검증한다.
- [ ] 엑셀 다운로드 제한을 권한, 건수, 사유, 승인 기준으로 적용한다.
- [ ] 다운로드 사유 입력과 다운로드 이력 기록을 적용한다.
- [ ] 대량조회 제한과 페이지네이션을 적용한다.
- [ ] 개인정보 조회, 수정, 삭제, 다운로드, 권한 변경을 감사로그에 기록한다.
- [ ] 감사로그 위변조 방지와 열람권한 제한을 적용한다.
- [ ] 첨부파일 접근 제한과 만료 링크 또는 인증 다운로드를 적용한다.
- [ ] 이미지/사진 개인정보 포함 가능성을 촬영 안내, 업로드 안내, 마스킹, 접근권한으로 관리한다.
- [ ] 테스트 데이터 비식별화 기준을 적용하고 실제 개인정보 사용을 금지한다.
- [ ] 백업 데이터 보관/파기 기준을 운영 배치와 복구 절차에 반영한다.
- [ ] 계정 비활성화와 퇴사자 권한 회수 절차를 적용한다.
- [ ] API 키, 토큰, 시크릿을 암호화하고 로그·응답·화면에 노출하지 않는다.
- [ ] 장애 대응 시 운영자 접근 기록과 접근 사유를 남긴다.
- [ ] 개인정보 파기 배치 또는 수동 파기 절차를 둔다.
- [ ] 고객사 계약 종료 시 데이터 반출, 보관, 파기, 접근권 회수 절차를 둔다.
