# SmartReturn Pro 반품 MVP 필드/컬럼 표시 목록

이 문서는 SmartReturn Pro 신규 제작 기준이며, 기존 SmartReturn 구현기록을 그대로 따르지 않는다.

이 문서는 실제 React 컬럼 정의 코드가 아니다. 실제 화면 구현 전에 어떤 필드를 어디에 표시할지, 어떤 필드는 숨길지, 어떤 필드는 상세/관리자 모드에서만 볼지 고정하는 기준 문서다.

## 1. 문서 목적

- SmartReturn Pro 반품 MVP 5개 화면의 표시 필드와 그리드 컬럼을 고정한다.
- 화면 구현자가 임의로 컬럼을 늘리거나 내부값을 운영 기본 UI에 노출하지 못하도록 한다.
- 작업자 화면과 관리자 화면의 표시 정보를 분리한다.
- 중앙 그리드와 우측 정보패널의 정보 우선순위를 명확히 한다.
- `raw_json`, `batch_id`, `import_job_id`, `row_hash`, `idempotency_key` 같은 내부값의 기본 노출을 금지한다.

## 2. 공통 표시 원칙

- 화면별 컬럼은 업무 목적에 맞게 최소화한다.
- 내부 식별자와 개발자용 값은 운영 기본 UI에 노출하지 않는다.
- 중앙 그리드는 현재 업무 판단에 필요한 핵심 정보만 표시한다.
- 우측 정보패널은 선택 행의 상세, 참고 정보, 다음 행동을 표시한다.
- 하단 액션바는 현재 단계에서 눌러야 하는 버튼과 상태만 표시한다.
- 작업자 스캔 화면은 컬럼 수를 줄이고 스캔, 판정, 완료 흐름을 우선한다.
- 관리자 조회/준비 화면은 필터와 검증 정보가 필요하지만, 안내문이 그리드를 밀어내면 실패다.
- 컬럼이 많으면 그리드 내부 가로 스크롤을 사용한다.
- 핵심 버튼을 그리드 가로 스크롤 뒤에 넣지 않는다.
- 상태는 코드값만 표시하지 말고 한글 상태명과 `SmartStatusBadge` 기준으로 표시한다.

## 3. 운영 기본 UI 노출 금지 필드

아래 필드는 운영 기본 UI에 직접 노출하지 않는다.

- `id`
- `raw_json`
- `metadata_json`
- `batch_id`
- `import_job_id`
- `source_job_id`
- `source_row_id`
- `row_hash`
- `source_row_key`
- `idempotency_key`
- `reverse_event_id`
- `internal_event_id`
- `created_by` 내부 ID
- `updated_by` 내부 ID
- Google credential 관련 값
- `spreadsheet_id` 전체값
- `local_event_id`
- stack trace
- DB error 원문

정책:

- 필요한 경우 관리자 상세, 개발자 상세, 감사 로그에서만 표시한다.
- 작업자 화면에는 절대 기본 노출하지 않는다.
- 운영자에게 필요한 경우 “작업번호”, “업로드번호”, “행번호”처럼 사용자용 표시명으로 변환한다.

## 4. 공통 표시 변환 규칙

### 4-1. 운송장번호

저장/비교:

- `waybill_no_norm`

화면 표시:

- `waybill_no_display`

정책:

- DB 비교는 하이픈과 공백을 제거한 정규화값 기준으로 한다.
- 화면에는 보기 좋은 형식으로 표시한다.
- 입력값은 자동 정규화한다.

### 4-2. 고객사

내부값:

- `client_id`

화면 표시:

- `client_name`
- `client_code` 보조 표시 가능

정책:

- `client_id` 숫자만 표시하지 않는다.
- 고객사 사용자는 자기 고객사 기준으로만 표시한다.

### 4-3. 창고

내부값:

- `warehouse_id`
- `location_id`

화면 표시:

- `warehouse_name`
- `location_code` 또는 `location_name`

정책:

- 선택 고객사의 사용창고만 표시한다.
- 창고 ID 숫자만 표시하지 않는다.

### 4-4. 상품

내부값:

- `product_id`

화면 표시:

- `product_code`
- `product_name`
- `barcode`

정책:

- `product_id` 숫자만 표시하지 않는다.
- 작업자 화면에서는 상품명과 스캔 판단에 필요한 바코드 정보를 우선한다.

### 4-5. 판정상태

내부값:

- `judgement_code`

화면 표시:

- `judgement_name`
- `SmartStatusBadge`

| 내부값 | 한글 표시 |
| --- | --- |
| `GOOD` | 양품 |
| `HOLD` | 보류 |
| `DISPOSAL` | 폐기 |
| `REFURB_A` | 리퍼A |
| `REFURB_B` | 리퍼B |
| `REFURB_C` | 리퍼C |
| `MANUFACTURER_RETURN` | 제조사반품 |
| `SAMPLE` | 샘플 |

표시 필드:

컬럼 후보:

- 상품코드
- 상품명
- 바코드
- 예정수량
- 스캔수량
- 판정수량
- 판정상태
- 라벨상태
- 반품관리번호
- 목적창고

작업자 기본 표시 컬럼:

- 상태
- 상품명
- 예정
- 스캔
- 판정
- 라벨

숨김 또는 상세로 이동:

- 사진/메모
- 라벨 출력/재출력 상태

하단 액션:

- 보류
- 라벨 재출력
- 처리완료
- 다음 운송장
- 초기화

금지:

- 구글시트 동기화
- 업로드 이력
- 기간별 배치조회
- 마감확정
- 반출묶음 생성
- 재고 이벤트 재처리

### 6-3. 운송장 조회 결과 카드

`lookup_case`별 표시 문구:

| `lookup_case` | 표시 문구 |
| --- | --- |
| `EXPECTED_AND_RECEPTION_FOUND` | 예정자료와 업체 접수자료가 모두 있습니다. |
| `EXPECTED_ONLY` | 택배 반품예정 자료만 있습니다. |
| `RECEPTION_ONLY` | 업체 접수자료만 있습니다. |
| `NOT_FOUND` | 등록된 예정/접수 자료가 없습니다. 고객사와 상품이 확인된 경우 수동 처리 후보입니다. |
| `ALREADY_COMPLETED` | 이미 처리 완료된 운송장입니다. |
| `MULTIPLE_CANDIDATES` | 복수 후보가 있습니다. 후보 선택 또는 관리자 확인이 필요합니다. |

정책:

- 조회 결과 카드는 버튼처럼 보이지 않게 한다.
- 작업자가 다음 행동을 바로 알 수 있도록 `next_action`을 함께 표시한다.

## 11. 컬럼 우선순위 기준

| 구분 | 기준 |
| --- | --- |
| 필수 컬럼 | 기본 화면에 항상 표시한다. |
| 보조 컬럼 | 화면 폭이 충분하면 표시한다. |
| 상세 컬럼 | 우측 패널 또는 상세 모달에서 표시한다. |
| 내부 컬럼 | 운영 기본 UI에 노출하지 않는다. |

정책:

- 1366x768에서 필수 컬럼이 우선 보이게 한다.
- 보조 컬럼 때문에 필수 컬럼이 밀리면 실패다.
- 내부 컬럼은 개발자 상세 또는 관리자 상세 후보로만 둔다.
- 작업자 화면은 필수 컬럼을 더 엄격히 줄이고 스캔 입력과 하단 액션을 우선한다.

## 12. Codex 구현 전 체크

- 이 필드는 작업자가 지금 판단하는 데 필요한가?
- 이 컬럼이 중앙 그리드에 있어야 하는가, 우측 패널에 있어야 하는가?
- 내부값을 운영 기본 UI에 노출하고 있지 않은가?
- 필수 컬럼이 너무 많아져 그리드가 망가지지 않는가?
- 상태값은 한글 표시명과 배지로 보이는가?
- 반품처리 작업 화면에 관리자용 컬럼을 넣고 있지 않은가?
- 반품자료 준비 화면에 판정/마감/반출 컬럼을 넣고 있지 않은가?
- 통합추적 화면에 조작 버튼을 넣고 있지 않은가?
