# SmartReturn Pro UI 페이지 템플릿

이 문서는 SmartReturn Pro 신규 제작 기준이다. 기존 SmartReturn의 구현기록, 화면, 스타일을 그대로 따르지 않는다.

이 문서는 단순 색상/스타일 문서가 아니라 샘플 디자인을 일관되게 구현하기 위한 페이지 골격 계약서다. 화면별로 느낌만 맞추는 것을 금지하고, 공통 구조와 배치 원칙을 기준으로 화면을 만든다.

## 공통 골격

- 좌측 메뉴: 업무 영역과 메뉴 이동을 담당한다.
- 상단 헤더/타이틀: 현재 화면명, 주요 상태, 핵심 보조 액션만 표시한다.
- 중앙 메인 그리드/작업영역: 화면의 주된 업무가 수행되는 영역이다.
- 우측 정보패널: 선택 행, 처리 상태, 요약 정보, 보조 판단 정보를 표시한다.
- 하단 액션바: 저장, 확정, 취소, 처리 같은 주요 업무 액션을 고정 배치한다.

## 공통 레이아웃 원칙

- 그리드가 화면의 주인공이어야 한다.
- 그리드만 화면 크기에 따라 늘어나고 입력, 버튼, 우측패널, KPI는 임의로 늘어나지 않는다.
- 안내문과 카드가 그리드를 밀어내면 실패다.
- 1366x768 기준 핵심 입력, 그리드 첫 5행, 우측 패널, 하단 액션바가 보여야 한다.
- 화면이 좁아질 때도 핵심 작업 흐름이 사라지면 안 된다.

## 화면 타입 1. 대시보드형

### 목적
업무 상태를 빠르게 파악하고 우선순위가 높은 업무로 진입한다.

### 기본 레이아웃
상단에는 핵심 KPI를 간결하게 배치하고, 중앙에는 업무별 상태 목록이나 예외 목록을 둔다. 우측 정보패널은 선택된 업무 상태의 상세 요약을 보여준다.

### 들어갈 것
- 핵심 KPI
- 예외/지연/오류 목록
- 업무 진입 버튼
- 기준일 또는 조회 조건

### 넣지 말 것
- 대량 편집
- 업로드 처리
- 확정 처리
- 상세 설정

### 실패 기준
- KPI 카드가 화면 대부분을 차지해 실제 업무 목록을 밀어내는 경우
- 클릭할 수 없는 정보 카드가 버튼처럼 보이는 경우
- 대시보드에서 업무 확정까지 처리하려는 경우

## 화면 타입 2. 관리자 조회형

### 목적
운영자가 데이터를 조회, 필터링, 비교하고 필요한 상세로 이동한다.

### 기본 레이아웃
상단 필터, 중앙 그리드, 우측 선택 상세, 하단 보조 액션으로 구성한다.

### 들어갈 것
- 필터 조건
- 정렬/검색 가능한 그리드
- 선택 행 상세
- 내보내기나 상세 이동 같은 조회 보조 액션

### 넣지 말 것
- 대량 업무 확정
- 스캔 입력
- 업로드 검증
- 설정 변경

### 실패 기준
- 필터 패널이 과도하게 커져 그리드 첫 5행이 보이지 않는 경우
- 조회 화면에서 처리, 판정, 마감 액션을 함께 수행하는 경우

## 화면 타입 3. 업로드/검증형

### 목적
원본 파일을 업로드하고 검증 오류를 확인한 뒤 업무 반영 준비 상태를 만든다.

### 기본 레이아웃
상단에는 업로드 입력과 고객사/창고 기준을 두고, 중앙에는 원본 preview 또는 검증 결과 그리드를 둔다. 우측에는 오류 요약과 매핑 상태를 표시한다.

### 들어갈 것
- 파일 선택 또는 붙여넣기 진입
- `SmartExcelPreviewGrid`
- 검증 결과
- 오류 목록
- import job 상태

### 넣지 말 것
- 실제 재고 반영
- 판정 확정
- 마감 확정
- 업무 원장 상세 편집

### 실패 기준
- 원본 preview가 textarea로 대체되는 경우
- 업로드 화면에서 업무 처리까지 끝내려는 경우
- `batch_id`를 업무 처리 중심키처럼 사용하는 경우

## 화면 타입 4. 작업자 스캔형

### 목적
현장 작업자가 바코드 또는 운송장번호를 빠르게 스캔하고 결과를 확인한다.

### 기본 레이아웃
상단에는 작업 기준을 고정하고, 중앙에는 큰 스캔 입력과 최근 스캔 목록을 둔다. 우측에는 Local Agent 상태와 선택 스캔 상세를 표시하며, 하단에는 작업 완료/보류 액션을 둔다.

### 들어갈 것
- 스캔 입력
- 최근 스캔 이벤트
- 매칭 결과
- Local Agent 연결상태/처리모드/프린터/사운드 상태
- 작업 완료 또는 보류 액션

### 넣지 말 것
- 구글시트 동기화
- 업로드 이력 조회
- 기간별 배치조회
- 재고 이벤트 상세 분석

### 실패 기준
- 스캔 중 외부 API 호출이 업무 저장을 막는 경우
- Local Agent 실패가 업무 저장 실패가 되는 경우
- 스캔 화면에서 재고를 직접 변경하는 경우

## 화면 타입 5. 판정형

### 목적
작업 결과를 기준으로 정상, 불량, 보류, 누락 등 업무 판정을 확정한다.

### 기본 레이아웃
중앙에는 판정 대상 그리드를 두고, 우측에는 선택 대상의 사진, 사유, 메모, 후보 정보를 표시한다. 하단 액션바에는 판정 저장과 보류 처리를 둔다.

### 들어갈 것
- 판정 대상 목록
- 판정 사유
- 보류 사유
- 후보 상품/수량 정보
- 판정 저장 액션

### 넣지 말 것
- 원본 업로드
- 마감 확정
- 반출 묶음 생성
- 재고 이벤트 상세 편집

### 실패 기준
- 후보 정보가 실제 확정값처럼 저장되는 경우
- 라벨 출력 실패를 판정 저장 실패로 처리하는 경우
- 판정 화면에 업로드와 마감을 함께 넣는 경우

## 화면 타입 6. 마감/대조형

### 목적
업무 완료 대상과 예외를 대조하고 마감 가능한 상태를 확정한다.

### 기본 레이아웃
상단에는 기준 기간과 고객사/창고 조건을 두고, 중앙에는 대조 결과 그리드를 둔다. 우측에는 예외 요약과 마감 영향도를 표시하고, 하단에는 마감 확정 액션을 둔다.

### 들어갈 것
- 마감 대상 목록
- 예외 목록
- 대조 결과
- 마감 전 검증 상태
- 마감 확정 액션

### 넣지 말 것
- 신규 업로드
- 스캔 작업
- 개별 판정 입력
- 기준정보 설정

### 실패 기준
- 마감 화면에서 누락 데이터를 임의 생성하는 경우
- 예외 상태가 해결되지 않았는데 마감 가능으로 보이는 경우
- 대조 결과와 업무 원장의 경계가 불분명한 경우

## 버튼과 비버튼 구분 기준

- 클릭 가능한 요소는 버튼, 링크, 메뉴, 그리드 행 선택처럼 역할이 분명해야 한다.
- 클릭 불가능한 카드/패널에는 `cursor:pointer`와 hover shadow를 주지 않는다.
- 정보 카드/패널은 버튼처럼 보이면 안 된다.
- 주요 업무 액션은 하단 액션바 또는 명확한 버튼 영역에 배치한다.
