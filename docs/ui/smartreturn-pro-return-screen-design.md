# SmartReturn Pro 반품 MVP 화면별 상세 설계

이 문서는 SmartReturn Pro 신규 제작 기준이며, 기존 SmartReturn 구현기록을 그대로 따르지 않는다.

이 문서는 실제 React 구현 지시가 아니다. 실제 화면 구현 전에 반품 MVP 화면의 책임, 레이아웃, 공통 컴포넌트, 금지 기능, 실패 기준을 고정하기 위한 기준 문서다.

## 공통 화면 설계 원칙

- 반품 화면은 업무 목적 1개만 가진다.
- 한 화면에 업로드, 조회, 이력, 처리, 판정, 마감, 반출, 설정을 섞지 않는다.
- 중앙 메인 그리드/작업영역이 화면의 주인공이어야 한다.
- 안내문, KPI 카드, 우측 패널이 중앙 그리드나 작업영역을 밀어내면 실패다.
- 전체 페이지 가로 스크롤은 금지한다.
- 데이터 그리드의 가로 스크롤은 그리드 내부에서만 허용한다.
- 하단 액션바는 항상 보여야 한다.
- 버튼이 아닌 카드/정보패널은 버튼처럼 보이면 안 된다.
- 클릭 가능한 요소만 `cursor:pointer`와 hover 강조를 사용할 수 있다.
- 입력창, 버튼, 우측 패널, KPI 카드 크기는 임의로 늘어나지 않는다.
- 그리드와 메인 작업영역만 남는 공간을 차지한다.
- 1366x768 기준으로 핵심 입력, 그리드 첫 5행, 우측 정보패널, 하단 액션바가 보여야 한다.
- 현장 작업자 화면에는 내부 enum, DB 필드명, 개발자 용어를 노출하지 않는다.
- 같은 의미의 안내문은 한 화면에 1회만 표시한다.
- 일반 카드/노란 안내 카드는 sticky로 고정하지 않는다.
- 긴 화면은 제목과 핵심 작업바만 sticky로 둔다.

## 반품 화면 목록

반품 MVP 화면은 아래 5개로 나눈다.

| 화면 | 화면 타입 | 핵심 책임 |
| --- | --- | --- |
| 반품자료 준비 | 업로드/검증형, 관리자 조회형 | CJ/택배 반품예정 자료를 검증하고 저장한다. |
| 반품처리 작업 | 판정형, 작업자 스캔형 | 실제 도착 반품을 스캔하고 상품/수량/판정을 확정한다. |
| 반품 마감 | 마감/대조형 | 판정 완료 결과를 실물 기준으로 대조하고 마감한다. |
| 반품 반출 | 작업자 스캔형, 마감/대조형 | 외부반출 대상 반품 개체를 스캔 대조하고 반출확정한다. |
| 반품 통합추적 | 관리자 조회형 | 반품 전 과정을 읽기 전용으로 조회한다. |

## 반품자료 준비 화면

### 화면 목적

CJ/택배 반품예정 자료를 내부 반품예정 업무 데이터로 만드는 화면이다. 업체 구글시트 동기화, 반품 판정, 반품 마감, 반품 반출은 이 화면에서 하지 않는다.

### 사용자

- 내부 운영자: 반품예정 자료 등록, 검증, 저장, 저장자료 조회를 수행한다.
- 고객사 사용자는 1차 MVP에서 기본 조회 중심으로 제한하며, 업로드 허용 여부는 후속 권한 정책에서 확정한다.

### 화면 타입

- 업로드/검증형
- 관리자 조회형

### 기본 레이아웃

- 좌측: 작업 메뉴
- 상단: 화면 제목, 고객사 선택, 자료구분, 작업 버튼
- 중앙: 업로드 preview 또는 저장자료 그리드
- 우측: 검증 요약, 고객사 미매칭, 중복/오류 요약
- 하단: 이전, 검증, 저장, 저장자료 조회, 업로드 이력 버튼

### 상단 영역

- 화면 제목은 "반품자료 준비"로 표시한다.
- 고객사 선택은 내부 운영자에게만 제공하며 `SmartLookupModal` 또는 `SmartCommonCodeSelect` 기준을 따른다.
- 자료구분은 CJ/택배 반품예정 자료 기준으로 제공한다.
- 현재 단계는 엑셀 등록, 붙여넣기 등록, 저장자료 조회, 업로드 이력 중 하나로 명확히 표시한다.

### 중앙 메인 영역

- 엑셀 등록: `SmartExcelPreviewGrid`
- 붙여넣기 등록: `SmartEditableDataGrid`
- 저장자료 조회: `SmartDataGrid`
- 업로드 이력: `SmartDataGrid`
- preview 그리드는 원본 row 순서와 검증 상태를 함께 보여준다.
- 저장자료 그리드는 업무용 `return_expected_rows` 기준으로 보여주며 원본 디버깅 필드를 기본 노출하지 않는다.

### 1366x768 통과 기준

- 고객사 선택, 자료구분, 현재 단계가 상단에 보여야 한다.
- preview 또는 저장자료 그리드 첫 5행이 보여야 한다.
- 우측 검증 요약이 접히거나 겹치지 않고 보여야 한다.
- 저장 확정, 오류행 보기 같은 핵심 버튼이 스크롤 없이 보여야 한다.

### 실패 기준

- preview 그리드가 화면 아래로 밀려 첫 화면에서 거의 보이지 않는다.
- 저장 버튼이 스크롤해야 보인다.
- 구글시트 관련 탭이 이 화면에 들어간다.
- `batch_id`, `import_job_id`, `raw_json`이 기본 UI에 직접 노출된다.
- 우측 패널이 중앙 그리드 위에 겹친다.

- 판정, 라벨, 재고, 마감, 반출 기능이 들어가지 않았는가?

## 반품처리 작업 화면

### 화면 목적

실제 도착한 반품을 운송장 또는 입고번호로 조회하고, 상품 확인, 판정, 사진/메모, 라벨, 처리완료를 수행하는 작업자 화면이다.

### 사용자

- 내부 작업자: 스캔, 상품 확인, 판정, 처리완료를 수행한다.
- 내부 관리자: 예외 처리와 보류 확인을 수행할 수 있다.
- 고객사 사용자는 기본적으로 직접 판정/처리하지 않는다.

### 화면 타입

- 판정형
- 작업자 스캔형

### 기본 레이아웃

- 상단 고정 영역: 화면 제목, 운송장 스캔/조회, 고객사/운영단위/처리모드/현재상태 요약
- 중앙 좌측: 상품 추가, 상품 스캔/검색/선택, 세부항목 없음 현장 상품 추가
- 중앙 메인: 처리 대상 상품 그리드, 처리상태/수량/판정/창고 표시
- 우측 또는 하단: 선택 상품 상세, 수량, 고객사별 판정, 창고 자동배정/선택, 메모/사진, AI도우미
- 하단 액션: 선택 처리, 보류, 처리완료, 초기화

### 상단 영역

- 큰 운송장 입력창
- 상품 스캔 입력창
- 현재 고객사
- 현재 창고
- Local Agent 연결상태
- 프린터/사운드 상태

### 중앙 메인 영역

- 운송장 조회 후 해당 운송장/입고번호의 대상 상품만 표시한다.
- 전체 반품 목록을 먼저 보여주지 않는다.
- 다음 처리 대상 row를 강조한다.
- 상품명, 상품코드, 예정수량, 스캔수량, 판정수량, 판정상태, 라벨상태를 표시한다.
- 복수 후보가 있는 경우 후보 선택 상태를 명확히 보여주고 자동 확정하지 않는다.

### 우측 정보패널

- 운송장 정보
- 업체 접수 참고정보
- 택배 반품예정 참고정보
- 현재 선택 상품 정보
- 판정 버튼
- 목적 창고 추천

### 작업자 문구 기준

```text
운송장 찍는다.
상품 확인한다.
판정한다.
창고 확인한다.
처리완료 누른다.
```

내부 표현은 작업자 표현으로 바꾼다.

| 내부 표현 | 작업자 표현 |
| --- | --- |
| `NO_DETAIL_MANUAL_INTAKE` | 현장 수동 처리 |
| `row 생성` | 상품 추가 |
| `return_tracking_no` | 반품 운송장번호 |
| `original_tracking_no` | 원운송장번호 |
| `GRID_SELECT` | 선택 처리 |
| `SCAN` | 스캔 처리 |

자세한 기준은 `docs/business/return-processing-workflow-ux-design.md`를 따른다.

### 운송장 조회 케이스 표시

| 케이스 | 화면 동작 |
| --- | --- |
| 예정자료와 접수자료 모두 있음 | 두 참고정보를 우측 패널에 표시하고 작업자가 상품/수량/판정을 확정한다. |
| 예정자료만 있음 | 택배 반품예정 정보를 참고로 보여주되 상품/수량 확정은 작업자가 한다. |
| 접수자료만 있음 | 업체 접수 정보를 참고로 보여주되 실제 도착 확인과 상품 스캔을 요구한다. |
| 둘 다 없음 | 고객사/상품이 현장에서 확인되면 수동 처리 후보로 진행한다. 확인 불가 시 미확인 보관/보류로 분리한다. |
| 이미 처리 완료 | 중복 처리 차단 메시지와 기존 처리 결과로 이동할 수 있는 읽기 동선을 제공한다. |
| 복수 후보 있음 | 후보 선택 또는 관리자 확인을 요구하고 자동 확정하지 않는다. |

### 넣지 말아야 할 기능

- 구글시트 동기화
- 반품예정 엑셀 업로드
- 업로드 이력
- 기간별 배치조회
- 반품 마감
- 반품 반출 묶음 생성
- 재고 이벤트 상세 재처리
- 정산 정보

### 1366x768 통과 기준

- 운송장 입력창과 상품 스캔 입력창이 상단에 보여야 한다.
- 현재 고객사, 창고, Local Agent 상태가 한눈에 보여야 한다.
- 중앙 상품 그리드 첫 5행 또는 현재 작업 대상이 보여야 한다.
- 판정 버튼과 처리완료 버튼이 스크롤 없이 보여야 한다.
- 최근 스캔 결과가 하단에서 잘리지 않아야 한다.

### 실패 기준

- 운송장 입력창이 화면 아래로 밀린다.
- 판정 버튼이 스크롤해야 보인다.
- 구글시트 동기화 버튼이 있다.
- 전체 배치 목록이 먼저 보인다.
- 작업자가 다음에 무엇을 해야 하는지 알 수 없다.
- 카드/안내문이 그리드를 밀어낸다.
- 라벨 출력 실패로 판정 저장이 실패하도록 설계된다.
