# 반품 운영 판정 정책

## 목적

이 문서는 SmartReturn Pro에서 반품 판정, 창고 확정, 재고반영, 세부항목 없는 반품, 스캔/그리드 처리, 부품적출 흐름을 설계하거나 수정할 때 따르는 기준이다.

반품 판정은 단순 상태값이 아니라 고객사별 운영 정책, 창고 위치, 후속 재고/반출/폐기 흐름을 결정하는 업무 행위다.

## 고객사별 판정 항목

반품 판정은 고객사마다 다르다. 반품처리 화면은 공통 고정 판정 버튼을 기본값처럼 사용하지 않고, 고객사별 판정 설정에 등록된 항목을 우선 표시한다.

예시:

```text
세분화 고객사:
양품 / 리퍼A / 리퍼B / 리퍼C / 샘플 / 제조사반출 / 폐기 / 부품적출

단순 고객사:
양품 / 리퍼 / 샘플 / 폐기
```

설정이 없을 때만 테스트 또는 초기 운영 fallback 판정 세트를 사용할 수 있다. 운영 기능을 만들 때는 고객사별 판정 설정을 먼저 확인한다.

## 판정별 창고 확정

반품 판정 시 `warehouse_id`는 필수다. 판정은 재고반영 위치를 결정하므로 `warehouse_id`가 확정되지 않은 row는 처리완료 또는 재고반영으로 진행하면 안 된다.

기본 흐름:

```text
판정 선택
→ 고객사별 판정 설정 확인
→ default_warehouse_id 자동 배정
→ requires_warehouse_selection이면 작업자가 창고 선택/확인
→ allowed_warehouse_ids가 있으면 허용 창고만 선택
→ warehouse_id 확정
→ 처리완료 가능
```

일반적으로 팀/창고 분기가 필요한 판정:

- 양품
- 제조사반출

일반적으로 기본 창고 자동 배정으로 충분한 판정:

- 리퍼A
- 리퍼B
- 리퍼C
- 리퍼
- 샘플
- 폐기

단, 실제 동작은 고객사별 설정을 우선한다. 화면이나 service에서 판정별 창고를 하드코딩하지 않는다.

## 재고반영 기준

재고반영은 아래 scope를 기준으로 한다.

```text
agency_id
+ client_id
+ client_unit_id
+ warehouse_id
+ product_id
+ judgment_code
+ quantity
```

반품 판정 즉시 `current_inventory`를 변경하지 않는다.

반품 흐름:

```text
반품 판정/처리완료
→ 현재고 변경 없음
→ 일마감 대기
→ 일마감 확정
→ 판정/창고 기준 재고반영
```

제조사반출, 폐기, 부품적출 등은 일마감 이후 월마감 또는 반출/폐기 확정 단계에서 추가 재고 이동, 차감, 상태변경을 수행한다.

## 세부항목 없는 반품 처리

반품처리 화면에서 운송장번호를 스캔했는데 업체 세부항목 또는 CJ 매칭 row가 없어도 처리를 막지 않는다. 반품 자료 등록 화면으로 보내는 것은 보조 경로이며, 현장 처리를 막는 기본 흐름이 되면 안 된다.

흐름:

```text
운송장 스캔
→ 세부항목 없음
→ 세부항목 없는 반품 모드
→ 상품바코드/상품코드 스캔 또는 상품 검색/선택
→ row 생성
→ 수량 입력/카운팅
→ 판정/창고 확정
→ 처리완료
→ 일마감 대기
```

상품마스터에 없는 상품은 정상 처리완료하지 않는다. 확인필요 또는 보류로 분리하고, 권한자가 상품 연결 또는 등록을 마친 뒤 처리한다.

처리모드 예시:

- `NORMAL_MATCHED`
- `NO_DETAIL_MANUAL_INTAKE`
- `UNKNOWN_TRACKING_MANUAL_INTAKE`

## 스캔 처리와 그리드 선택 처리

조회형 작업 화면은 스캔 처리와 그리드 선택 처리를 모두 지원한다.

적용 대상:

- 반품처리
- 일마감 수량 확인
- 제조사반출/폐기/부품적출
- 일반 입고
- 일반 출고검수
- 세트/구성품 피킹/검수

처리방식 예시:

- `SCAN`
- `GRID_SELECT`
- `MANUAL_QUANTITY`
- `BULK_CONFIRM`

그리드 선택 처리도 backend의 같은 처리수량 검증, 중복처리 방지, 권한 검증, warehouse scope 검증, 이력 저장을 반드시 거친다. frontend에서 선택만 했다는 이유로 backend 검증을 우회하지 않는다.

## 부품적출

부품적출은 폐기 메모가 아니다. 폐기 전 재사용 가능한 부품을 분리해 재고화하는 별도 작업 흐름이다.

흐름:

```text
폐기/부품적출 대상
→ 적출 가능한 부품 확인
→ 적출 수량 입력
→ 적출 부품 창고 확정
→ 적출 부품 재고반영
→ 잔여품 폐기 확정
```

부품적출 결과는 최소 아래 기준으로 이력화한다.

```text
agency_id
client_id
client_unit_id
source_product_id
extracted_product_id
warehouse_id
quantity
condition_status
worker
timestamp
memo/photo
```

부품적출도 판정/창고/재고 scope를 지켜야 한다. 적출 부품이 상품마스터에 없으면 정상 부품재고로 반영하지 않는다.

## 금지 방향

- 고객사별 판정 설정을 무시하고 공통 버튼만 사용하지 않는다.
- `warehouse_id` 없이 처리완료하지 않는다.
- 반품 판정 즉시 `current_inventory`를 변경하지 않는다.
- 세부항목 없는 반품을 처리 불가로 막지 않는다.
- 상품마스터에 없는 상품을 정상 처리완료하지 않는다.
- 그리드 선택 처리를 frontend 상태 변경만으로 끝내지 않는다.
- 부품적출을 폐기 메모나 단순 사유값으로만 남기지 않는다.
