# Worker Screen UX Skill

## 목적

SmartReturn Pro 작업자용 화면의 UX 기준을 정리한다.

## 대상 화면

- 입고검수
- 출고검수
- 반품처리
- 반품마감 수량체크
- 반품 외부반출 검수
- 재고실사/수량체크

작업자 화면은 관리자 조회 화면처럼 만들지 않는다.

## 핵심 원칙

1. 정확도
2. 속도
3. 자동화

작업자는 화면을 읽는 시간이 아니라 스캔하고 판단하고 다음 단계로 넘어가는 시간이 중요하다.

## 스캔 화면 기준

- 큰 스캔 입력창을 둔다.
- 스캔 입력 묶음은 `SmartScanPanel` 또는 그에 준하는 공통 스캔 패널을 사용한다.
- 현재 해야 할 작업을 한눈에 표시한다.
- 성공, 오류, 초과, 중복, 미등록 피드백을 크게 표시한다.
- 가능하면 Enter 또는 스캔만으로 다음 단계로 진행한다.
- 마우스 클릭을 최소화한다.
- 포커스를 자동 이동한다.
- 불필요한 필터, 탭, 검색 조건을 최소화한다.

## 버튼 기준

- 작업자가 매번 판단해야 하는 버튼을 줄인다.
- 판정 버튼은 크고 명확하게 만든다.
- 위험 작업은 확인 단계를 두되 반복 작업 속도를 해치지 않는다.
- 기본값이 명확한 작업은 자동 적용하고 예외만 수정하게 한다.

## 그리드 기준

- 작업자에게 필요한 컬럼만 표시한다.
- 관리자용 상세 컬럼은 숨기거나 별도 상세로 분리한다.
- 다음 처리 대상 row를 강조한다.
- 처리 완료, 오류, 보류 상태가 즉시 구분되어야 한다.
- 운송장번호, 상품코드, 바코드, 반품관리번호처럼 스캔/대조에 쓰는 값은 copyable 셀 기준을 따른다.

## 반품처리 화면 흐름

반품처리 화면은 아래 흐름을 방해하지 않는 UI로 구성한다.

1. 운송장 스캔
2. 상품 스캔 또는 확인
3. 판정
4. 사진/메모 필요 시 입력
5. 라벨 출력 기본값 적용
6. 완료

## 메뉴 이동과 작업 복원

- SmartReturn 주요 업무 화면은 메뉴 이동 후에도 마지막 조회조건, 그리드 상태, 선택 row, 처리중 작업을 가능한 범위에서 기억해야 한다.
- 좌측 메뉴 클릭으로 화면에 진입할 때는 스크롤 위치를 맨 위로 초기화한다. 검색조건/필터는 유지할 수 있어도 작업자는 화면 제목과 주요 작업 영역을 먼저 봐야 한다.
- 상단 작업 탭으로 복귀할 때는 마지막 작업 상태를 복원할 수 있다. 단, 화면 제목과 현재 작업 맥락은 sticky page title 또는 sticky 작업바로 계속 보여야 한다.
- 반품처리 화면은 운송장번호와 선택 row를 복원하되, 실제 처리중/완료 상태는 backend 조회 결과를 기준으로 다시 확인한다.
- 스캔 입력 중 Enter 직전 값, 파일 선택, 저장/처리완료/마감/재고반영 버튼 상태는 복원하지 않는다.
- 저장, 처리완료, 마감, 재고반영 같은 확정 액션은 복원만으로 다시 실행되지 않게 backend 상태와 버튼 disabled 조건을 재검증한다.
- 작업 탭은 최근 업무 화면 전환을 돕는 보조 장치이며, 무한정 열지 않고 오늘 작업/반품 처리 같은 핵심 화면을 고정 탭으로 둘 수 있다.

## 스캔과 그리드 선택

- 조회형 작업 화면은 스캔 처리와 그리드 선택 처리를 모두 지원할 수 있어야 한다.
- 그리드 선택 처리도 스캔 처리와 같은 backend 검증, 권한 확인, 처리수량 검증, 중복처리 방지, 이력 저장을 거친다.
- 세부항목 없는 반품은 반품처리 화면 안에서 상품 스캔 또는 상품 검색/선택으로 row를 만들 수 있어야 한다.
- 세트상품은 작업자에게 “세트/구성품” 중심으로 보여주고, “BOM” 같은 내부 용어를 과다 노출하지 않는다.
- AI 판정도우미는 짧은 체크리스트와 추천 사유를 제공하되, 최종 판정은 작업자가 확정한다.

관련 기준은 `return-operational-judgment-policy.md`, `set-product-component-bom.md`, `return-judgment-ai-assistant.md`를 따른다.

## 작업자 화면 문구

- 현장 작업자 화면에는 내부 enum, DB 필드명, `row 생성` 같은 개발자 용어를 노출하지 않는다.
- 세부항목 없는 반품은 “상품 추가 → 판정 → 창고 확정 → 처리완료” 흐름으로 안내한다.
- 안내문은 중복하지 않고, 사용자가 지금 해야 할 다음 행동을 짧게 보여준다.
- 자료 등록/원자료 보정은 보조 경로로 낮추고, 현장 처리를 막는 메인 액션처럼 보이게 하지 않는다.

## 넣지 말아야 할 것

작업자 화면에는 아래를 기본으로 넣지 않는다.

- 과한 통계
- 복잡한 필터
- 관리자용 원본 데이터 버튼
- 재고 이벤트 수동 처리
- 오류 재처리 관리자 기능
- 불필요한 설명 배너

## 로컬 장치 연동

소리, 라벨, 프린터, 스캐너 같은 로컬 장치가 필요한 경우 웹에서 억지로 구현하지 않는다. 필요하면 Local Agent 연동을 고려한다.

작업자 화면은 반드시 실제 업무 순서와 focus 순서를 먼저 설계한 뒤 구현한다.
