# 검수 체크포인트 — SmartReturn Pro

> Codex(검수자)가 Claude Code(구현자) 완료보고서를 검수할 때 적용한다.

## 기본 규칙

- 완료보고서를 그대로 믿지 않는다. 실제 파일/git/test/build/secret을 직접 확인한다.
- 검수 중 코드를 수정하지 않는다. 빨간불은 구현자(클코)로 되돌린다.
- git add/commit/push 금지.
- PASS / 부분통과 / FAIL 판단을 하나의 text 코드블록으로 보고한다.

## AI 작업 기본 원칙 체크포인트

구현자가 아래 원칙을 지켰는지 결과물로 확인한다.
(상세 원칙 정본: AGENTS.md §AI 작업 기본 원칙)

| 원칙 | 검수자 확인 항목 |
|---|---|
| 작업 전 판단 | 스펙/목표가 명확히 이해됐는가? 모호한 부분을 물었거나 선택지를 제시했는가? |
| 단순 우선 | 요청 범위 밖 기능·추상화가 추가됐는가? 필요 이상 복잡한 구현은 없는가? |
| 최소 수정 | 작업 범위 밖 파일이 수정됐는가? (`git diff`로 확인) |
| 검증 기준 | "통과" 표시 항목이 실제로 검증됐는가? 미실행 항목이 통과로 표시됐는가? |

## SmartReturn Pro 핵심 원칙 확인

- `client_id` / `agency_id` / `warehouse_id` scope 누락 없는지 확인한다.
- 권한·데이터 차단이 프론트가 아니라 백엔드 API에서 강제됐는지 확인한다.
- secret/.env/local.secret/token/key 노출 여부 확인한다.
- 커밋 후보와 제외 파일을 분리했는지 확인한다.
