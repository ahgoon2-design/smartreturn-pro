# 세트상품/구성품/BOM 기준

## 목적

이 문서는 SmartReturn Pro에서 세트상품, 구성품, BOM, 부품을 출고와 반품 업무에 연결할 때 따르는 기준이다.

핵심 문장:

```text
세트상품은 주문/판매 단위이고, 구성품은 실제 피킹/검수/재고 단위다.
```

시스템 내부에서는 BOM 구조를 사용할 수 있지만, 현장 작업자 화면에는 “BOM”이라는 용어를 과다 노출하지 않는다. 화면에서는 “세트/구성품” 중심으로 표현한다.

## 상품 유형

권장 상품 유형:

- `SINGLE`: 단품
- `SET`: 세트 대표상품
- `COMPONENT`: 구성품
- `PART`: 적출 부품 또는 수리 부품

상품 유형은 출고, 반품, 재고, 부품적출에서 같은 의미로 사용한다.

## 출고에서의 사용

예시:

```text
판매상품: 쿠팡 조리도구 4종 선물세트
구성품:
- 조리도구 A 1개
- 조리도구 B 1개
- 조리도구 C 1개
- 조리도구 D 1개
```

주문:

```text
쿠팡 조리도구 4종 선물세트 10개
```

시스템 전개:

```text
조리도구 A 10개 필요
조리도구 B 10개 필요
조리도구 C 10개 필요
조리도구 D 10개 필요
```

출고 방식은 두 가지를 지원할 수 있게 설계한다.

1. 주문 시 조립형 세트
   - 주문이 들어오면 구성품을 피킹해 세트로 포장한다.
   - 출고 확정 시 구성품 재고를 차감한다.
   - 초기 구현은 이 방식을 우선해도 된다.

2. 사전 조립형 세트
   - 미리 구성품 재고를 차감하고 세트 완제품 재고를 생성한다.
   - 출고 시 세트 재고를 차감한다.
   - 초기에는 미구현이어도 되지만 확장 가능하게 설계한다.

## 반품에서의 사용

세트상품이 반품으로 들어오면 구성품 체크리스트를 자동 표시한다.

예시:

```text
조리도구 A 정상
조리도구 B 정상
조리도구 C 누락
조리도구 D 파손
```

구성품 누락/파손은 판정 추천과 최종 판정에 영향을 준다.

예시:

- 필수 구성품 모두 있음 + 상품 정상 → 양품 가능
- 필수 구성품 누락 → 양품 불가, 리퍼/보류/구성품누락 추천
- 본체 파손 + 일부 구성품 정상 → 부품적출 추천

반품처리 화면은 작업자가 구성품을 빠르게 확인할 수 있어야 한다. 단, 내부 BOM 코드나 복잡한 재고 용어를 현장 화면에 길게 노출하지 않는다.

## 부품적출 연결

폐기/부품적출 대상이 세트상품이면 구성품/부품 기준으로 적출 가능 여부를 표시한다.

예시:

```text
무선청소기 세트 폐기

적출:
- 배터리 1개 정상
- 충전기 1개 정상

폐기:
- 본체 1개 파손
- 브러시 2개 오염

결과:
- 배터리 부품재고 +1
- 충전기 부품재고 +1
- 본체 폐기완료 +1
```

적출 부품은 `PART` 또는 고객사 정책상 지정된 구성품 상품으로 관리한다. 적출 결과는 `agency_id`, `client_id`, `client_unit_id`, 원상품, 적출상품, 창고, 수량, 상태, 작업자, 시간, 증빙을 남길 수 있어야 한다.

## UX 원칙

시스템 내부는 복잡해도 사용자는 편하게 써야 한다.

작업자 원칙:

```text
스캔한다
보이는 대로 확인한다
이상 있으면 체크한다
완료 누른다
```

시스템이 자동으로 처리해야 할 것:

- 세트 여부 확인
- 구성품 자동 표시
- 필요수량 자동 계산
- 구성품 누락/초과 표시
- 판정 영향 안내
- 출고 재고차감 기준 결정
- 부품적출 가능 여부 안내

## 설계 주의사항

- 세트 대표상품과 구성품 재고를 동시에 차감해 이중 차감하지 않는다.
- 주문 시 조립형인지 사전 조립형인지 출고 정책을 명확히 둔다.
- 반품 판정 시 구성품 상태가 최종 판정에 미치는 규칙을 고객사별로 관리한다.
- 구성품 검사와 부품적출은 스캔 처리와 그리드 선택 처리를 모두 지원할 수 있게 설계한다.
- 고객사별 상품마스터에 없는 구성품/부품은 정상 재고 처리하지 않는다.
