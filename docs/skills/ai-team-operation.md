# AI 팀 운영 기준

## 1. 목적

- SmartReturn Pro에서 Codex, Claude, ChatGPT를 동시에 사용할 때 역할이 흔들리지 않도록 고정한다.
- 이 문서는 작업 큐, 보고, 충돌 방지, 커밋 통제 기준이다.
- 각 도구가 같은 목표를 보더라도 수정 범위와 검증 책임을 분리해 작업 품질을 안정화한다.

## 2. 기본 개념

- 똘망이는 별도 작업자 1명이 아니다.
- 똘망이는 팀 운영 방식, 작업 큐, 보고 체계, 커밋 통제 프레임이다.
- 똘망이는 개발팀 운영 프레임이고, 똘순이는 사업팀 운영 프레임이다.
- Claude와 Codex는 똘망이 큐 안에서 각자 역할을 수행한다.
- ChatGPT는 Codex/Claude 보고를 받아 다음 큐를 설계하는 지휘소 역할을 한다.

## 3. 역할 분담

### Claude Code

기본 역할 — 구현자이자 검수자 (Codex와 교차):
- 파일 수정과 코드 구현
- 버그 수정, 빌드/타입 오류 수정
- 화면 제작
- UX와 레이아웃 정리
- 화면 문구 보정
- 사용자 흐름 검토
- 화면 구조 검토
- 정책과 리스크 검토
- 독립 검수·테스트·build·diff·커밋 게이트도 수행 (Codex 구현분 검수 시)

### Codex

기본 역할 — Claude Code와 동급 기본 구현자:
- 코덱은 클코와 동급 기본 구현자다. 코드 작성, 버그 수정, API/타입 안정화를 수행한다.
- 독립 검수, 테스트, build, diff, 커밋 게이트도 수행한다.
- 구현이냐 검수냐는 작업별로 배정하며, 사용량이 남은 쪽에 구현을 준다.
- 같은 작업에서 구현자와 최종 검수자는 다르다 (교차검수).

### ChatGPT

- Codex/Claude 보고 취합
- 충돌 파일 정리
- 살릴 변경과 되돌릴 변경 판단
- 커밋 범위 설계
- 다음 똘망이 큐 생성

### 똘순이

- 사업계획, 영업, 가격, 운영정책, 법무·재무 리스크, 고객 공개 문서 초안 작성
- business-auditor 검수와 사장님 승인 필요 여부 표시
- 개발 구현이 필요하면 사업 목적, 고객 공개 여부, 운영정책, 금지 조건, 필요한 화면/API/데이터 변경 후보, 검수 상태, 남은 보류를 묶어 똘망이로 인수

## 4. 지시문 기본 구조

SmartReturn Pro 지시문은 가능하면 아래 구조를 표준으로 둔다.

- 똘망이 운영 큐
- Claude 작업 카드
- Codex 작업 카드
- 최종 취합 기준
- 완료 보고 형식

사용자가 지시문 작성을 요청하면 복사하기 쉽도록 하나의 text 코드블록으로 정리한다.

## 5. 동시 작업 원칙

- Claude와 Codex를 동시에 돌릴 때는 수정 가능 파일과 금지 파일을 분리한다.
- Claude는 화면, UX, 문구, 레이아웃 중심 파일을 담당한다.
- Codex는 구현, 검증, 빌드 안정화, 테스트 중심 파일을 담당한다.
- 같은 파일을 동시에 수정해야 하면 먼저 보고하고 충돌 가능성을 명시한다.
- 한 작업자가 다른 작업자의 변경분을 무단으로 덮어쓰지 않는다.
- 작업 전 `git status --short`로 현재 변경 파일을 확인하고, 기존 변경분은 사용자 또는 다른 작업자의 작업으로 간주한다.

## 6. 커밋 원칙

- 커밋은 사용자 승인 전 하지 않는다.
- 의미 있는 작업 단위가 완료되고 검증이 끝난 뒤 선별 커밋한다.
- 커밋 전 `git status --short`, `git diff --check`, 관련 테스트 또는 build 결과를 확인한다.
- frontend/backend/Claude/Codex 변경분이 섞이면 `git add .`를 피하고 선별 stage한다.
- secret, `.env`, `local.secret.json`, 로그, 빌드 산출물, 캐시 파일은 커밋하지 않는다.

## 7. 완료 보고 기준

완료 보고에는 아래를 포함한다.

- 수정 파일
- 핵심 변경
- 검증 결과
- 충돌 가능성
- 커밋 여부
- 남은 이슈
- 다음 추천 작업

사용자가 보고 형식을 지정했으면 그 형식을 우선하며, 복사하기 쉬운 보고가 필요하면 하나의 text 코드블록으로 정리한다.

## 8. 금지사항

- secret, `.env`, `local.secret.json`, API key, 비밀번호, 토큰을 읽거나 출력하거나 커밋하지 않는다.
- backend와 frontend 범위를 사용자 지시 없이 섞지 않는다.
- Claude 작업 파일을 Codex가 무단으로 덮어쓰지 않는다.
- Codex 작업 파일을 Claude가 무단으로 덮어쓰지 않는다.
- 문서 작업은 기준을 고정하는 목적일 때만 수행한다. 구현 작업에서는 문서만 늘리고 검증 없이 완료 보고하지 않는다.
- 오래 막히는 브라우저 검증은 10~15분 이상 끌지 말고 수동 확인 필요로 보고한다.
