# SmartReturn 화면 디자인 시스템 스킬

## 목적

SmartReturn Pro의 모든 신규 화면, 화면 개편, UI 수정, 아이콘/이미지 추가 작업에서 따라야 하는 화면 디자인 기준을 정리한다.

SmartReturn Pro는 단순 반품 프로그램이 아니라 OMS + WMS + Returns 통합 운영 플랫폼이다. 화면은 구형 ERP처럼 딱딱하면 안 되고, 과하게 화려해서 현장 작업성을 해쳐도 안 된다. 목표는 사용자 편의성이 높은, 은은한 빛이 도는 현대적인 물류 운영 SaaS 화면이다.

## 디자인 철학

SmartReturn Pro의 화면은 “은은한 빛이 도는 현대적인 물류 운영 SaaS”를 목표로 한다.

- 사용자가 하루 종일 보는 업무 화면이므로 눈이 피로하지 않아야 한다.
- 현장 작업자는 빠르게 스캔하고 판단해야 하므로 입력, 버튼, 상태가 명확해야 한다.
- 관리자는 많은 데이터를 봐야 하므로 그리드, 필터, 상태 badge, 요약 카드가 일관되어야 한다.
- 고객사는 자기 반품, 재고, 처리상태를 쉽게 이해해야 하므로 전문 용어를 최소화하고 상태 설명을 명확히 해야 한다.

금지 방향:

- 구형 ERP처럼 회색 표만 가득한 화면
- 진한 원색으로 눈이 피로한 화면
- 화면마다 다른 버튼, 모달, 카드 스타일
- 안내문이 너무 많아 작업을 방해하는 화면
- 색상 의미가 화면마다 달라지는 디자인
- 스캔 작업 화면에서 작은 입력창이나 작은 버튼 사용
- 화면별 임시 table, modal, select, style 남발
- 이미지 파일 아이콘을 화면마다 직접 추가하여 스타일이 섞이는 것

## 전체 색상 방향

진한 원색은 피하고, 은은한 파스텔 톤과 부드러운 배경빛을 사용한다.

기본 색상 역할:

- 푸른빛: 정보, 조회, 자동수집, 정상 진행, 기본 primary
- 연두빛: 성공, 완료, 입고완료, 재고반영, 정상 처리
- 주황빛: 확인필요, 보류, 주의, 수동확인, 작업대기
- 붉은빛: 오류, 차단, 실패, 삭제 위험
- 보라빛 또는 남색빛: 관리자, 설정, 권한, 시스템 작업
- 회색빛: 비활성, 보조정보, 완료된 과거자료, 원본참조

중요:

- 화면 전체를 색으로 칠하지 않는다.
- 카드 뒷배경, 상태 badge, 아이콘, border, 작은 강조 영역에만 색을 사용한다.
- 같은 의미의 상태는 모든 화면에서 같은 색상 계열을 사용한다.
- 진한 배경에 흰 글씨를 남발하지 않는다.
- 경고/오류 외에는 높은 채도의 빨강을 사용하지 않는다.

- Ant Design token, CSS variable, 공통 class 중 하나로 통일한다.
- 화면별 inline color를 남발하지 않는다.

## 은은한 빛이 도는 카드 디자인

카드/패널은 다음 스타일을 기본으로 한다.

- 흰색 또는 아주 연한 배경
- 12~16px `border-radius`
- 연한 border
- 강하지 않은 `box-shadow`
- 카드 상단 또는 좌측에 아주 연한 색상 glow
- 상태별로 배경빛만 다르게 표현
- 진한 컬러 박스 지양

예시:

- 자동수집 카드: 푸른빛 배경
- 완료 카드: 연두빛 배경
- 확인필요 카드: 주황빛 배경
- 오류 카드: 붉은빛 배경, 단 사용 최소화

권장 CSS 느낌:

```css
background: linear-gradient(135deg, #ffffff 0%, #f3f8ff 100%);
border: 1px solid rgba(185, 220, 248, 0.72);
box-shadow: 0 8px 24px rgba(15, 23, 42, 0.06);
```

주의:

- shadow가 너무 강하면 안 된다.
- 여러 카드가 붙어 있을 때 색상 과다 사용을 피한다.
- 카드 하나 안에 너무 많은 정보를 넣지 않는다.

## 아이콘/이미지 규칙

작은 기능 아이콘은 SVG 라인 아이콘으로 통일한다.

기본 원칙:

- 작은 기능 아이콘은 이미지 파일(PNG/JPG/WebP)을 직접 추가하지 않는다.
- SVG 아이콘 라이브러리를 우선 사용한다.
- 권장 라이브러리는 `lucide-react` 또는 `@ant-design/icons`이다.
- 아이콘은 얇고 깔끔한 line icon 스타일을 기본으로 한다.
- 메뉴, 버튼, 상태 badge, KPI 카드, 빈 상태 화면, 안내 패널에 아이콘을 사용할 수 있다.
- 아이콘은 기능을 보조하는 용도이며, 아이콘만으로 중요한 의미를 전달하지 않는다.
- 중요한 버튼/상태에는 반드시 텍스트를 함께 표시한다.

아이콘 색상:

- 정보/조회/자동수집: 푸른빛
- 완료/성공/재고반영: 연두빛
- 확인필요/보류/주의: 주황빛
- 오류/차단/실패: 붉은빛
- 설정/권한/시스템: 보라빛 또는 남색빛
- 비활성/보조정보: 회색빛

이미지 파일 사용 허용 범위:

- SmartReturn 로고
- 고객사 로고
- 상품 사진
- 반품/검수/증빙 사진
- 설명용 일러스트
- 빈 상태용 공통 일러스트
- 문서/홍보용 이미지

이미지 파일 사용 금지/주의:

- 메뉴 아이콘을 PNG/JPG로 직접 추가하지 않는다.
- 버튼 아이콘을 이미지 파일로 만들지 않는다.
- 상태 아이콘을 화면별 이미지 파일로 만들지 않는다.
- 화면마다 다른 스타일의 아이콘 세트를 섞지 않는다.
- 과도한 3D/그림체/캐릭터 아이콘을 업무 화면에 남발하지 않는다.
- 아이콘 파일을 새로 추가하기 전에 기존 아이콘 라이브러리에서 대체 가능한지 먼저 확인한다.

권장 아이콘 스타일:

- 선이 얇고 단순한 line icon
- 둥근 모서리와 부드러운 느낌
- 물류, 창고, 반품, 재고, 자동화 업무에 어울리는 형태
- 색상은 상태 규칙에 맞춘 단색 또는 은은한 배경 원 안에 배치
- 작은 크기에서도 의미가 읽히는 형태

아이콘 크기 기준:

- 메뉴 아이콘: 16~20px
- 버튼 아이콘: 14~18px
- KPI 카드 아이콘: 20~28px
- 빈 상태 아이콘: 40~64px
- 작업자 화면 주요 상태 아이콘: 32~48px 가능

접근성:

- 아이콘만 있는 버튼은 `aria-label` 또는 tooltip을 제공한다.
- 중요한 상태는 색상과 아이콘만으로 표시하지 말고 텍스트를 함께 표시한다.
- 색약 사용자를 고려해 색상만으로 상태를 구분하지 않는다.

## 레이아웃 규칙

기본 화면 구성:

- `SmartPage`
- `SmartPageHeader`
- `SmartSummaryCard` 또는 `SmartKpiCard`
- `SmartToolbar`
- `SmartDataSection`
- `SmartDataGrid`
- `SmartActionBar`

기본 구조:

1. 상단: 화면 제목, 설명, 주요 액션
2. 요약: 상태/KPI 카드
3. 필터: 검색/상태/기간/고객사/창고
4. 본문: 그리드 또는 작업 패널
5. 하단: 주요 저장/완료 action bar

규칙:

- 1366×768 기준으로 업무 가능해야 한다.
- 상단/하단이 너무 높아 본문이 좁아지면 안 된다.
- 업무 핵심 영역이 첫 화면에 보여야 한다.
- 스크롤은 중간 본문에 주고, 주요 액션은 하단 또는 우측에 고정한다.
- 모달이 너무 커지면 별도 화면 또는 drawer/panel을 고려한다.

## 작업 탭/상태 유지 UX

- 좌측 메뉴는 업무 진입, 상단 작업 탭은 최근 작업 전환 역할로 분리한다.
- 좌측 메뉴 클릭으로 화면에 진입할 때는 스크롤 위치를 맨 위로 초기화한다. 조회조건, 필터, 그리드 상태는 유지할 수 있지만 화면 제목과 주요 작업 영역이 먼저 보여야 한다.
- 상단 작업 탭 복귀는 마지막 route/query와 작업 상태를 복원할 수 있다. 필요 시 스크롤 위치 복원도 가능하지만, 확정 액션은 backend 상태로 재검증한다.
- 작업 탭은 무한정 늘리지 않고 최근 5~7개 안에서 유지한다. 오늘 작업, 반품 처리 같은 핵심 화면은 고정 탭으로 둘 수 있다.
- 주요 업무 화면은 메뉴 이동 후에도 마지막 조회조건, 그리드 상태, 선택 row, 처리중 작업을 가능한 범위에서 기억해야 한다.
- 긴 업무 화면은 화면 제목과 핵심 작업바가 사라지지 않도록 `SmartPageHeader` 또는 공통 sticky class를 우선 적용한다.
- 조회조건, 필터, 탭 값은 URL query를 우선 사용하고, 최근 작업 탭과 그리드 부가 상태는 sessionStorage를 우선 사용한다.
- 저장, 처리완료, 마감, 재고반영 같은 확정 액션은 화면 복원으로 중복 실행되면 안 되며 backend 상태를 기준으로 재검증한다.

## 관리자 화면 디자인 규칙

관리자 화면은 고객사 관리, 상품 관리, 채널 연동 관리, 코드/설정 관리, 이력 조회, 재고 조회, 대시보드에 적합해야 한다.

규칙:

- 상단 요약 카드로 전체 상태를 먼저 보여준다.
- 필터는 접기/펼치기 가능하거나 한 줄 중심으로 둔다.
- 데이터는 `SmartDataGrid`를 기본 사용한다.
- 상태는 `SmartStatusBadge`로 표시한다.
- 위험 액션은 확인 모달을 사용한다.
- 생성/수정은 `SmartModalShell` 또는 공통 상세 패널을 사용한다.
- 화면마다 다른 테이블, 모달, 버튼 스타일을 만들지 않는다.
- 아이콘은 기능 보조용으로 사용하되, 텍스트 없이 아이콘만으로 관리자 기능을 노출하지 않는다.

## 작업자/스캔 화면 디자인 규칙

작업자 화면은 반품처리, 입고 스캔, 출고 검수, 외부반출 검수, 일마감 수량 체크, 라벨 출력/재출력에 적합해야 한다.

규칙:

- 스캔 입력창은 크고 명확하게 보여야 한다.
- 현재 작업 상태를 큰 카드로 보여준다.
- 성공/오류/보류/중복/수량초과는 색상과 문구가 즉시 구분되어야 한다.
- 버튼은 손으로 누르기 쉬운 크기여야 한다.
- 스캔 흐름을 방해하는 모달은 최소화한다.
- 오류는 짧고 명확한 문장으로 표시한다.
- 하단 `SmartActionBar`에 주요 액션을 둔다.
- 작업자는 작은 글씨의 표를 계속 읽지 않아도 되게 한다.
- 주요 상태에는 큰 상태 아이콘을 사용할 수 있으나, 아이콘만으로 의미를 전달하지 않는다.

색상:

- 정상 스캔: 연두빛
- 다음 작업 대기: 푸른빛
- 확인 필요/보류: 주황빛
- 오류/차단: 붉은빛
- 완료: 연두빛 + 완료 badge

## 반품 판정/세트/AI 화면 기준

- 반품처리 화면은 고객사별 판정 버튼을 우선 표시하고, 판정별 `warehouse_id` 확정 상태를 작업자가 바로 알 수 있게 표현한다.
- 세부항목 없는 반품은 현장 작업자가 현재 화면에서 상품 스캔 또는 상품 검색/선택으로 row를 만들 수 있게 안내한다.
- 스캔 처리와 그리드 선택 처리는 UI는 달라도 같은 처리완료 검증과 이력 저장으로 이어져야 한다.
- 세트상품은 “세트/구성품” 중심으로 표시하고 작업자 화면에 “BOM” 같은 내부 용어를 과다 노출하지 않는다.
- 부품적출은 폐기 메모가 아니라 폐기 전 별도 작업 흐름으로 표현한다.
- AI 판정도우미는 추천 판정, 추천 이유, 확인 체크리스트를 보조 영역으로 제공하되 최종 판정 버튼보다 앞서거나 자동 확정처럼 보이면 안 된다.

상세 업무 기준은 `return-operational-judgment-policy.md`, `set-product-component-bom.md`, `return-judgment-ai-assistant.md`를 따른다.

## 고객사 포털 화면 디자인 규칙

고객사 포털은 내부 관리자 화면보다 더 쉽고 설명적이어야 한다.

규칙:

- 전문 용어를 줄인다.
- 상태 설명을 쉽게 제공한다.
- 고객사는 자기 `client_id`/`client_unit` 범위만 본다.
- 재고, 반품, 사진, 처리상태를 카드와 표로 쉽게 확인한다.
- 내부 운영용 버튼이나 위험 액션은 노출하지 않는다.
- “처리중”, “확인필요”, “완료”, “보류” 같은 고객 친화 문구를 사용한다.
- 아이콘은 이해를 돕는 보조 요소로만 사용한다.

## 상태 색상 규칙

상태별 색상 의미를 고정한다.

| 상태 그룹 | 예시 | 색상 |
| --- | --- | --- |
| 정상/정보 | `COLLECTED`, `READY`, `IN_PROGRESS`, 조회 가능, 자동수집 완료 | 푸른빛 |
| 완료/성공 | `COMPLETED`, `CLOSED`, `INVENTORY_APPLIED`, `GOOD`, `CREATED` | 연두빛 |
| 주의/확인필요 | `NEEDS_REVIEW`, `TEAM_ASSIGN_PENDING`, `PRODUCT_MATCH_PENDING`, `RETURN_TRACKING_PENDING`, `HOLD`, `WARNING` | 주황빛 |
| 오류/차단 | `ERROR`, `FAILED`, `BLOCKED`, `REJECTED` | 붉은빛 |
| 비활성/과거 | `INACTIVE`, `ARCHIVED`, `DISABLED`, `SKIPPED` | 회색빛 |
| 시스템/관리 | `ADMIN`, `CONFIG`, `PERMISSION`, `SYNC` | 보라빛 또는 남색빛 |

## 버튼 규칙

Primary 버튼:

- 화면의 가장 중요한 1개 액션만 primary로 둔다.
- 예: 저장, 처리완료, 반품예정 생성, 일괄 생성

Secondary 버튼:

- 조회, 재처리, 새로고침, 보정에 사용한다.

Danger 버튼:

- 삭제, 차단, 취소, 거부에 사용한다.
- 반드시 확인 모달을 사용한다.

Ghost/Link 버튼:

- 상세보기, 이력보기, 복사 등 보조 액션에 사용한다.

규칙:

- 한 화면에 primary 버튼을 여러 개 남발하지 않는다.
- 위험 액션은 색상과 문구를 명확히 한다.
- 버튼 문구는 짧고 동사형으로 쓴다.
- “확인”만 쓰지 말고 “반품예정 생성”, “보정 저장”, “일마감 확정”처럼 명확히 쓴다.
- 버튼 아이콘은 SVG 아이콘 라이브러리를 사용한다.
- 버튼의 핵심 의미는 텍스트로 함께 제공한다.

## 그리드 규칙

기본은 `SmartDataGrid`를 사용한다.

규칙:

- 운송장번호, 상품코드, 바코드 셀은 복사 가능해야 한다.
- 원본 row 순서가 중요한 화면은 기본 정렬을 바꾸지 않는다.
- 상태는 badge로 표시한다.
- 긴 텍스트는 ellipsis + tooltip 또는 상세 패널로 처리한다.
- 컬럼이 많으면 가로 스크롤을 허용하되 스크롤이 보이게 한다.
- 작업자 화면에서는 표보다 현재 작업 카드/스캔 패널을 우선한다.
- 대량 목록은 페이지네이션을 둔다.
- `ERROR`/`WARNING`은 행 전체가 아니라 상태/사유 중심으로 은은하게 강조한다.
- 컬럼 아이콘은 보조용으로만 사용하고, 의미가 필요한 값은 텍스트를 함께 표시한다.

## 모달/상세 패널 규칙

모달은 `SmartModalShell` 또는 공통 모달 패턴을 사용한다.

규칙:

- 단순 입력/보정은 모달을 사용한다.
- 긴 상세/이력은 drawer 또는 별도 상세 화면을 고려한다.
- 모달 안에 그리드와 폼을 과도하게 넣지 않는다.
- 저장/취소 버튼 위치를 통일한다.
- 위험 작업은 확인 모달을 따로 둔다.
- 모달 제목은 작업 목적이 바로 보이게 쓴다.
- 예: “상품 매칭 보정”, “반품송장 입력”, “채널 계정 수정”

## 대시보드/KPI 카드 규칙

요약 카드는 다음 구조를 따른다.

- 제목
- 숫자
- 짧은 설명
- 상태 색상
- 필요 시 작은 SVG 아이콘
- 클릭 시 필터 연결 가능

색상 예:

- 오늘 수집: 푸른빛
- READY: 연두빛
- 확인필요: 주황빛
- 오류: 붉은빛
- 생성됨: 연두빛
- 비활성: 회색빛

주의:

- 카드 숫자가 너무 많으면 안 된다.
- 한 줄에 4~6개 정도가 적당하다.
- 모든 카드에 진한 색 배경을 넣지 않는다.
- 은은한 배경빛과 작은 badge 중심으로 표현한다.
- KPI 카드 아이콘은 같은 스타일, 두께, 크기로 통일한다.

## 문구/카피 규칙

업무 화면 문구는 짧고 명확해야 한다.

좋은 예:

- “반품송장 없음: 원송장만 있어 현장 스캔 기준 송장이 확정되지 않았습니다.”
- “상품매칭 필요: 상품코드/바코드 직접 매칭이 실패했습니다.”
- “팀배정 필요: 채널 계정에 운영단위가 지정되지 않았습니다.”
- “확인필요: 중복 송장 또는 외부 주문 충돌 가능성이 있습니다.”
- “차단: 필수 식별자/송장 정보가 부족해 자동 처리할 수 없습니다.”

나쁜 예:

- “오류”
- “실패”
- “처리할 수 없습니다.”
- “확인하세요.”
- 원인을 알 수 없는 긴 기술 오류 문장

## 금지 패턴

반드시 금지한다.

- 화면별 임시 table 직접 작성 남발
- 화면별 임시 modal/style 남발
- inline style 색상 남발
- 진한 원색 배경 남발
- 상태별 색상 의미가 화면마다 달라짐
- 작업자 화면의 작은 입력창/작은 버튼
- 불필요한 설명문 과다
- 모든 정보를 한 화면에 다 넣기
- 위험 액션에 확인 모달 없음
- `raw_json`/개인정보를 일반 화면에 노출
- 고객사 포털에 내부 운영용 버튼 노출
- 구형 ERP처럼 회색 표만 가득한 화면
- 디자인을 위해 업무 동선을 복잡하게 만드는 것
- 메뉴/버튼/상태 아이콘을 PNG/JPG 이미지로 직접 추가
- 화면마다 다른 스타일의 아이콘 세트 혼용
- 아이콘만 있고 텍스트가 없어 의미가 불분명한 버튼

## 새 화면 제작 체크리스트

새 화면을 만들거나 기존 화면을 개편할 때 반드시 확인한다.

- 이 화면은 관리자, 작업자, 고객사 중 누구를 위한 화면인가?
- 사용자가 이 화면에서 가장 먼저 해야 하는 일은 무엇인가?
- 첫 화면에서 핵심 상태가 보이는가?
- `SmartPage`/`SmartPageHeader`를 사용했는가?
- 요약 카드가 필요한 화면인가?
- 필터/검색 위치가 일관적인가?
- `SmartDataGrid`를 사용할 수 있는가?
- 상태는 `SmartStatusBadge`로 표현했는가?
- 주요 액션은 한눈에 보이는가?
- 위험 액션은 확인 모달이 있는가?
- 1366×768에서 사용 가능한가?
- 운송장/상품코드/바코드 복사 정책을 지켰는가?
- 색상 의미가 기존 규칙과 일치하는가?
- 아이콘은 SVG 라이브러리를 사용했는가?
- 아이콘만으로 중요한 의미를 전달하고 있지 않은가?
- 새 이미지 파일을 추가했다면 로고, 상품사진, 증빙사진, 일러스트 등 허용 범위인가?
- 개인정보, secret, `raw_json` 노출 위험은 없는가?
- 화면별 임시 스타일을 만들지 않았는가?
