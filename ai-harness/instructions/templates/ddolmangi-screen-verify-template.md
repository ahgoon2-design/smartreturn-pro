# 똘망이 화면 브라우저 검증 템플릿

실행대상: 똘망이(Playwright 브라우저)
선행: Claude 화면 제작 완료(build 통과 상태)

> 서버 5173/8000 가동 확인 후 진행. 쓰기(저장/확정)는 테스트 식별자 데이터만 사용. 기존 실데이터 클릭/확정 금지. 10~15분 이상 막히면 중단·보고.
> Karpathy 보강분 A~D 적용 (AGENTS.md 참조)

## 1. 로그인 계정
- 내부: `ahgoon`(SUPER_ADMIN) / 대리점: `517593`(AGENCY_ADMIN) / 고객: `ESPMARKETING` 등(CLIENT_ADMIN) — 검증할 role별로 명시
- 비밀번호는 로컬 테스트 공통값(보고서에 값 기재 금지)

## 2. 진입 route
- 대상: `/<route>` (지시문의 route 그대로. 직접 URL 진입 + 메뉴 진입 둘 다)

## 3. 화면 렌더 확인
- [ ] 헤더 제목/설명 노출, 빈 흰 화면 아님
- [ ] 주요 영역(필터/그리드/우측 패널/액션바) 렌더
- [ ] 1366x768 리사이즈 시 핵심 요소 보임

## 4. 버튼/그리드/필터/검색/저장 확인
- [ ] 필터/검색 동작(조회 결과 변화)
- [ ] 그리드: 행 렌더, 선택, 원본 순서, Ctrl+C/복사 아이콘
- [ ] rows>0일 때 엑셀 다운로드 버튼 노출(0건이면 미노출), 다운로드 파일에서 운송장/바코드 문자열 보존
- [ ] 저장/확정 버튼: 활성 조건 충족 시 동작(테스트 식별자 데이터 1건만)

## 5. 권한별 노출/disabled 확인
- [ ] 내부 계정: 허용 버튼 활성
- [ ] 고객 계정: 내부 전용 요소 미노출/disabled, 내부 route 접근 시 포털로 리다이렉트
- [ ] 권한 없는 계정: 버튼 disabled+사유 또는 미노출(빈 화면 아님)

## 6. 저장 성공/실패 메시지 확인
- [ ] 성공: 결과 메시지 노출 + 화면 상태 갱신(상태 배지/그리드)
- [ ] 실패(권한/스코프/정책 차단): backend 사유가 보이는지(일반 "실패" 한 줄로 덮이지 않는지)
- [ ] 저장 후 재고/상태가 정책과 일치(예: 처리완료 시 재고 미반영 안내)

## 7. 브라우저 콘솔 오류 확인
- [ ] error 레벨 0건 목표(favicon 404, 미인증 401 등 무해 항목은 사유와 함께 분리 기록)

## 8. 데이터 없을 때 처리 확인
- [ ] 0건 조회 시 emptyText/안내 노출, 버튼 상태 적절
- [ ] 데이터가 없어 확인 불가한 항목은 "필요한 최소 데이터"와 함께 분리 보고(대규모 시드 금지)

## 9. 보고서 위치
- `ai-harness/reports/<번호>-<화면명>-verify-report.md`

## 10. 통과/실패/확인불가 구분 (보고 양식)
```
[화면/route] [사용 계정]
통과: (항목 나열)
실패: (항목 + 재현 절차 + 콘솔/네트워크 근거 — 버그 후보)
확인불가: (항목 + 사유: 데이터 부족/위험 회피/환경)
버그 vs 데이터 부족 vs 위험 회피 구분 / 다음: Codex 검수 인계
```
