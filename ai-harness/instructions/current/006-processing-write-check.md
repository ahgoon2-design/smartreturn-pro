# 006 - 반품 처리 처리완료(쓰기) 검증

> 실행 전 `<PROJECT_ROOT>/AGENTS.md`, `CLAUDE.md`를 읽는다. 브랜치 `smartreturn-pro` 기준. main 병합/동기화 제안 금지, push 금지. 선행: 005 완료.

## 목표
`/returns/processing`에서 테스트 반품 1건을 **실제 처리완료**까지 검증한다.

## 담당 화면 또는 기능
- `/returns/processing` (반품 처리 센터)

## 사전 조건
- 005에서 준비한 테스트 처리대기 row(`V3WRITE-`) 존재
- GOOD 또는 REFURB_A 라우팅 설정 존재
- 테스트 데이터 식별자 확인 가능

## 실행 범위
- 테스트 데이터 **1건만** 처리완료.
- 가능하면 GOOD 1건 또는 REFURB_A 1건만 선택.
- 실제 버튼 클릭 전 대상 row가 `V3WRITE-` 테스트 데이터인지 반드시 확인.

## 필수 확인 항목
- [ ] 처리대기 row 조회
- [ ] row 선택 → 우측 판정 패널 표시
- [ ] GOOD 또는 REFURB_A 선택 가능
- [ ] 처리완료 전 확인 메시지/요약 표시
- [ ] 처리완료 성공(작업상태 "처리 완료")
- [ ] 처리완료 후 재고 즉시 미반영 안내
- [ ] 처리완료 건이 일마감 후보로 넘어갈 상태(상태값 확인)
- [ ] 잘못된 창고 라우팅이면 처리완료 차단되는지 기록

## 위험 회피 조건
- 테스트 식별자가 아닌 기존 데이터면 클릭 금지
- 다건 선택/일괄 처리 금지
- 창고 라우팅 불명확하면 처리완료 금지
- 실패 원인이 버그인지 데이터 부족인지 구분 보고

## 중단 조건
- 창고 라우팅 부재로 처리완료 차단 → 005 보완 항목 보고 후 중단
- 서버/브라우저 10~15분 이상 막힘 → 중단, 수동 확인 필요
- 앱 버그 발견 → 이번 단계에서는 **보고만**, 코드 수정 금지
