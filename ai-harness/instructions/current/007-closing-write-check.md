# 007 - 반품 일마감/재고반영(쓰기) 검증

> 실행 전 `<PROJECT_ROOT>/AGENTS.md`, `CLAUDE.md`를 읽는다. 브랜치 `smartreturn-pro` 기준. main 병합/동기화 제안 금지, push 금지. 선행: 006 완료.

## 목표
`/returns/closing`에서 006 처리완료 건을 **일마감**하고 재고반영 흐름을 확인한다.

## 담당 화면 또는 기능
- `/returns/closing` (반품 일마감/수량대조)

## 사전 조건
- 006에서 처리완료된 테스트 건(`V3WRITE-`) 존재
- 일마감 후보에 표시 가능한 상태
- 테스트 식별자 확인 가능

## 실행 범위
- 테스트 건 **1건만** 일마감/수량대조.
- 다른 후보를 함께 마감하지 않는다(가능하면 고객사/기간 필터로 `V3WRITE-`만 좁힌다).
- GOOD이면 상품바코드 수량대조 기준 확인, REFURB_A면 반품관리번호 1:1 대조 기준 확인.

## 필수 확인 항목
- [ ] 후보 목록에 테스트 건 표시
- [ ] 처리완료 전 자료가 후보에 섞이지 않음
- [ ] 수량대조 또는 반품관리번호 대조 방식이 판정과 일치
- [ ] 마감 확정 전 재고 미반영 상태
- [ ] 마감 확정 성공
- [ ] 마감 후 재고반영 안내/결과 확인(GOOD=양품재고, 비양품=정책상 분리)
- [ ] 동일 건 중복 마감 방지
- [ ] 다음 단계 외부반출 대상 여부 확인

## 위험 회피 조건
- 테스트 식별자가 아닌 후보 선택 금지
- 여러 건 동시 마감 금지
- 기존 데이터와 섞이면 중단
- 재고 차이 발생 + 원인 불명확하면 중단
- 마감 확정 버튼이 테스트 건만 대상으로 작동하는지 불명확하면 클릭 금지

## 중단 조건
- `V3WRITE-` 건만 안전 분리 선택 불가 → 확정하지 말고 중단·보고
- 서버/브라우저 10~15분 이상 막힘 → 중단, 수동 확인 필요
- 앱 버그 발견 → 보고만, 코드 수정 금지
