# 002 - 반품 일마감/수량대조 화면 브라우저 검증

> 실행 전 `<PROJECT_ROOT>/AGENTS.md`, `CLAUDE.md`를 읽는다. 브랜치 `smartreturn-pro` 기준. main 병합/동기화 제안 금지, push 금지, 앱 코드 수정 금지. 선행: 001 완료.

## 목표
처리완료 건이 일마감 후보로 보이고, 수량대조 → 마감확정 → 재고반영 흐름이 정책과 맞는지 확인한다.

## 화면 또는 기능
- 라우트: `/returns/closing` (메뉴: 반품 운영 > 일마감)
- (라우트가 다르면 실제 메뉴/라우팅에서 확인해 보고서에 기록)

## 사전 조건
- 처리완료(COMPLETED) 반품 1건 이상
- 상품바코드 수량대조 대상(GOOD 또는 DISPOSAL) 1건
- 가능하면 반품관리번호 1:1 대조 대상(REFURB_A/B/C 또는 MANUFACTURER_RETURN) 1건
- 데이터 없으면 최소 필요 데이터만 보고(대규모 시드 금지)

## 필수 확인 항목 (각 통과/실패 기록)
- [ ] 일마감 후보 목록 진입(기간/고객사/판정상태 조회)
- [ ] 처리완료 전 자료가 후보에 섞이지 않음
- [ ] GOOD/DISPOSAL = 상품바코드 기준 수량대조 흐름
- [ ] REFURB_A/B/C/MANUFACTURER_RETURN/SAMPLE/HOLD = 반품관리번호 1:1 대조 흐름
- [ ] 마감 확정 전 재고 즉시 미반영
- [ ] 마감 확정 후 재고반영 결과/안내 명확
- [ ] 차이(불일치) 있으면 마감확정 차단
- [ ] 중복 마감/중복 재고반영 방지 징후(이미 마감 자료가 후보로 안 보임)
- [ ] 조회형 그리드 엑셀 다운로드/복사 노출, 내부 enum 원문 미노출

## 데이터 없을 때 처리
- 대규모 시드 금지. 필요한 최소 데이터 + 001 단계에서 준비할 항목(처리완료 1건 등) 보고.
- 억지로 화면 수정하지 않는다.

## 수정 허용 범위
- 앱 코드 수정 금지(버그만 보고 후 최소 수정). 문서/보고서만.

## 중단 조건
- 서버/브라우저 10~15분 이상 막힘 → 중단, 수동 확인 필요 보고.
- 마감확정이 재고를 즉시 잘못 반영하는 등 위험 동작 → 즉시 중단·보고(임의 수정 금지).
