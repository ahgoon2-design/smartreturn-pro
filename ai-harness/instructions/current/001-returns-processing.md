# 001 - 반품 처리 화면 브라우저 검증

> 실행 전 `<PROJECT_ROOT>/AGENTS.md`, `CLAUDE.md`를 읽는다. 브랜치 `smartreturn-pro`(SmartReturn Pro 라인) 기준. main 병합/동기화 제안 금지, push 금지, 앱 코드 수정 금지.

## 목표
브라우저로 `/returns/processing`에서 처리대기 row 선택 → 판정 패널 노출까지 확인한다.

## 화면 또는 기능
- 라우트: `/returns/processing` (메뉴: 반품 운영 > 반품처리)

## 사전 조건
- 로컬 서버 5173(frontend)/8000(backend) 가용
- SUPER_ADMIN 계정 로그인 가능(예: `ahgoon`)
- 가능하면 처리대기(READY_FOR_PROCESSING) 반품 row 1건 이상
- 데이터 없으면 `tmp/` 일회성 최소 준비만, 대규모 시드 금지

## 필수 확인 항목 (각 통과/실패 기록)
- [ ] 헤더 "반품 처리 센터" 노출
- [ ] 운송장 스캔 패널 노출
- [ ] 1~5단계 strip(운송장 확인/상품 추가/판정/창고 확정/처리완료) 노출
- [ ] 처리대기 그리드 노출
- [ ] row 선택 시 우측 "선택 상품 처리" 판정 패널 노출
- [ ] `불량` 버튼 노출
- [ ] `리퍼A` / `리퍼B` / `리퍼C` 버튼 노출
- [ ] generic `리퍼` 단일 버튼 미노출
- [ ] rows>0일 때 그리드 "엑셀 다운로드" 버튼 노출 (0건이면 미노출)
- [ ] 운송장번호/상품코드/바코드 표시 + 셀 복사(Ctrl+C/복사 아이콘) 가능
- [ ] 처리완료 전/후 "재고 즉시 미반영" 안내 노출
- [ ] 세부항목 없는 반품 수동 처리 흐름(미매칭 운송장 → 상품 추가 패널) 정상

## 데이터 없을 때 처리
- 자동 시드/대규모 DB 작업 금지. 필요한 최소 데이터 종류(상품 1건 + 처리대기 반품 1건)만 보고.
- 판정 패널 확인 불가 시 사유 명시(데이터 부족 vs 버그 구분).

## 수정 허용 범위
- 앱 코드 수정 금지(명백한 버그만 보고 후 최소 수정). 문서/보고서만.

## 중단 조건
- 서버/브라우저 10~15분 이상 막힘 → 중단, "수동 확인 필요" 보고.
- 화면 깨짐/콘솔 치명 오류 → 원인 파일 기록 후 중단(다음 지시문으로 넘어가지 않음).
