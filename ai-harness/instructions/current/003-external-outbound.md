# 003 - 외부반출 검수 화면 브라우저 검증

> 실행 전 `<PROJECT_ROOT>/AGENTS.md`, `CLAUDE.md`를 읽는다. 브랜치 `smartreturn-pro` 기준. main 병합/동기화 제안 금지, push 금지, 앱 코드 수정 금지. 선행: 001~002 완료.

## 목표
REFURB_A/B/C·제조사반품 등 외부반출 대상이 후보로 나오고, 반품관리번호 스캔/검수/반출확정 흐름이 맞는지 확인한다.

## 화면 또는 기능
- 라우트: `/returns/external-outbound` (메뉴: 출고 > 반품 외부반출). 이력: `/returns/external-outbound/batches`
- (라우트가 다르면 실제 메뉴/라우팅에서 확인해 보고서에 기록)

## 사전 조건
- 외부반출 대상 데이터 1건 이상(REFURB_A/B/C 중 1건 권장)
- 가능하면 MANUFACTURER_RETURN 1건
- GOOD/DISPOSAL/HOLD 오포함 여부 확인용 데이터
- 데이터 없으면 최소 필요 데이터만 보고(대규모 시드 금지)

## 필수 확인 항목 (각 통과/실패 기록)
- [ ] 외부반출 후보 목록 진입
- [ ] REFURB_A/B/C가 외부반출 후보에 포함(누락 없음)
- [ ] legacy generic `REFURB` 데이터가 있으면 호환 조회, 충돌 없음
- [ ] GOOD/DISPOSAL/HOLD가 후보에 잘못 포함되지 않음
- [ ] `DEFECTIVE`가 외부반출 자동후보에 잘못 섞이지 않음
- [ ] 반품관리번호 1:1 스캔 검수 흐름
- [ ] 스캔 완료 후 반출확정 가능
- [ ] 반출확정 후 재고 차감/결과 안내 명확(서버 경로에서만 차감)
- [ ] 중복 반출/중복 재고차감 방지 징후(반품관리번호 중복 스캔 차단)
- [ ] 조회형 그리드 엑셀 다운로드/복사 노출

## 데이터 없을 때 처리
- 대규모 시드 금지. 필요한 최소 데이터 + 002 단계에서 필요한 마감 조건 보고.
- 자동화 구축으로 우회하지 않는다.

## 수정 허용 범위
- 앱 코드 수정 금지(버그만 보고 후 최소 수정). 문서/보고서만.

## 중단 조건
- 서버/브라우저 10~15분 이상 막힘 → 중단, 수동 확인 필요 보고.
- DEFECTIVE가 자동후보 노출 등 정책 위반 발견 → 즉시 중단·보고(임의 수정 금지).
