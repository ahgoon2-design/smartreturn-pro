# 똘고리 / Self-Fix Loop

## 1. 정체

똘고리는 구현자가 자기 테스트로 스스로 고쳐가며 도는 자가수정 루프다.

단, 혼자 폭주하지 않는다.

구현자는 자기테스트로 객관적 실패를 최대 3회까지 고칠 수 있지만, 최종 통과 판단은 반드시 구현자가 아닌 다른 쪽이 교차검수한다.

## 2. 기본 원칙

- 구현자는 자기 작업에 대해 빌드, 테스트, 타입체크, lint, smoke 확인 같은 객관 검증을 직접 수행할 수 있다.
- 객관 검증이 실패하면 같은 세션 안에서 최대 3회까지 자가수정할 수 있다.
- 같은 문제를 3회 고쳐도 해결하지 못하면 4번째 같은 방식으로 반복하지 않는다.
- 3회 실패 시 멈추고 원인, 시도 내역, 남은 위험, 다음 판단 필요 항목을 보고한다.
- 자기가 구현한 작업을 자기가 최종 통과 판정하지 않는다.
- 최종 검수는 구현자가 아닌 다른 쪽이 수행한다.
- 커밋은 수문장 검수와 사용자 승인 후에만 진행한다.

## 3. 루프 흐름

1. 구현
   - 담당자가 코드, 문서, 화면, 테스트를 작성하거나 수정한다.

2. 자기테스트
   - 담당자가 관련 빌드, 테스트, 타입체크, lint, smoke 확인을 직접 수행한다.

3. 자가수정
   - 빨간불이면 원인을 고치고 다시 자기테스트를 수행한다.
   - 같은 문제는 최대 3회까지만 반복한다.

4. 중단 보고
   - 같은 문제를 3회 고쳐도 해결되지 않으면 멈춘다.
   - 실패 원인, 시도한 수정, 남은 문제, 필요한 도움을 보고한다.

5. 구현 완료 보고
   - 자기테스트가 초록불이면 “구현 완료”로 보고한다.
   - 단, 이 보고는 최종 PASS가 아니다.

6. 교차검수
   - 구현자가 아닌 다른 쪽이 독립 검수한다.
   - 보고서를 그대로 믿지 않고 실제 파일, diff, 테스트, build, 권한, 경로, secret, 커밋 후보를 확인한다.

7. 재작업
   - 교차검수에서 빨간불이면 구현자에게 되돌린다.
   - 재작업 루프도 최대 3회 원칙을 따른다.

8. 사용자 인수
   - 교차검수 통과 후 사용자가 화면/흐름/보고를 확인한다.

9. 수문장
   - 커밋 전 Commit Gate를 통과한다.
   - git status --short, git diff --check, 관련 테스트/build, secret/산출물 제외, 선별 stage 대상 확인을 수행한다.

10. 커밋
   - 사용자가 명시 승인한 뒤에만 관련 파일을 선별 stage/commit한다.
   - push는 별도 승인 후에만 한다.

## 4. 자가검수 허용/금지 경계

### 구현자가 직접 확인해도 되는 것

아래는 기계적·객관적 검증이므로 구현자가 직접 확인할 수 있다.

- 빌드 통과/실패
- 테스트 green/red
- 타입체크 통과/실패
- lint 통과/실패
- import 가능 여부
- 서버 실행 여부
- API 응답 성공/실패
- git diff --check 결과
- secret 검색 결과
- 파일 존재 여부
- 브라우저 smoke 확인

### 다른 쪽이 봐야 하는 것

아래는 판단형 검수이므로 반드시 교차검수한다.

- 의도가 맞는가
- 작업 범위를 벗어나지 않았는가
- 빠진 케이스가 없는가
- 권한/테넌시/데이터 범위가 안전한가
- 재고/마감/정산 원칙을 깨지 않았는가
- 고객 화면에 내부 enum/DB 용어가 노출되지 않는가
- 커밋 후보와 제외 파일이 정확한가
- 보고서가 사실과 일치하는가
- 다음 작업으로 넘겨도 되는가

## 5. 역할 배정

### 클코(Claude Code)와 코덱(Codex)은 둘 다 기본 구현자다

- 클코와 코덱은 둘 다 기본 구현자다. 파일 수정, 코드 작성, 화면 수정, 버그 수정, 빌드/테스트 수행, 구현 완료 보고를 모두 할 수 있다.
- 구현은 사용량이 남은 쪽에 배정한다. 한 쪽이 구현을 전담하지 않는다.
- 둘 다 검수도 할 수 있다. 읽기전용 검수, 테스트/build 확인, diff 검수, 커밋 후보/제외 분리, 수문장/Commit Gate 수행도 둘 다 수행한다.
- 단 같은 작업(SPEC)에서 구현한 쪽과 최종 검수한 쪽은 반드시 다르다 (교차검수).
- 자기가 구현한 것을 자기가 최종 검수(판단형)하지 않는다.

### ChatGPT

기본 역할:
- 지휘소
- 작업 순서 판단
- 위험도 판단
- Claude Code/Codex 지시문 작성
- 완료 보고 해석
- 다음 작업 큐 결정
- 커밋 범위 판단 보조

### 교차검수 원칙

같은 작업에서 구현자와 최종 검수자는 달라야 한다.

예 (어느 쪽이 구현하든 검수는 반대쪽):
- 클코 구현 → 코덱 검수
- 코덱 구현 → 클코 검수

자기가 구현한 것을 자기가 최종 PASS 처리하지 않는다.

## 6. 똘망이 감독 기준

똘고리는 AGENTS.md와 ai-harness 규칙을 따른다.

적용 기준:
- 같은 오류 3회 반복 시 중단
- 같은 명령 3회 반복 시 중단
- 브라우저 검증 10~15분 이상 막히면 중단
- dirty 파일 혼입 금지
- 작업 범위 밖 파일 수정 금지
- secret, .env, local.secret, token, key, password 출력 금지
- git add . 금지
- git add -A 금지
- 관련 파일만 선별 stage
- commit은 사용자 승인 후
- push는 별도 승인 후
- 빨간불 무마 금지
- 실패를 PASS로 포장 금지
- 스코프 이탈 시 멈춤·보고

## 7. 수문장 연결

똘고리의 마지막 단계는 수문장이다.

수문장은 자동으로 아무거나 커밋하는 도구가 아니다.
수문장은 커밋 전 안전 게이트다.

수문장 확인 항목:
- git status --short
- git diff --check
- 관련 테스트/build 결과
- 변경 파일 목록
- 커밋 후보 파일
- 커밋 제외 파일
- secret/local 설정 제외
- build/dist/cache/logs/outputs/image/node_modules/.venv/__pycache__ 제외
- 사용자 승인 여부
- push 별도 승인 여부

## 8. 한계

현재 단계에서 똘고리는 완전 자동 멀티에이전트 루프가 아니다.

- 자가수정 3회는 각 AI 세션 안에서 수행한다.
- Claude Code ↔ Codex 교차검수 전달은 현재 사용자가 수동으로 한다.
- 지시문과 보고서는 사용자가 복붙한다.
- consensus-loop는 지시문/검수지시문/최종판단 생성을 도울 수 있지만, Claude Code/Codex를 자동 실행하지 않는다.
- 교차검수 전달 자동화, 훅, 브릿지는 다음 단계 작업이다.

## 9. 완료 판정

똘고리 루프의 완료는 아래 조건을 모두 만족해야 한다.

- 구현자 자기테스트 초록불
- 교차검수 PASS 또는 조건부 PASS
- 사용자가 필요한 화면/흐름 확인
- 수문장 통과
- 사용자 커밋 승인
- 선별 커밋 완료 또는 커밋 보류 사유 명확화

## 10. 금지

- 같은 문제를 4회 이상 같은 방식으로 반복하지 않는다.
- 자기가 구현한 작업을 자기가 최종 PASS 처리하지 않는다.
- 테스트 실패를 무시하지 않는다.
- 빌드 실패를 무마하지 않는다.
- 범위 밖 파일을 몰래 수정하지 않는다.
- dirty 파일을 섞어서 커밋하지 않는다.
- git add . 를 사용하지 않는다.
- git add -A 를 사용하지 않는다.
- 사용자 승인 없이 commit하지 않는다.
- 별도 승인 없이 push하지 않는다.
- secret, .env, local.secret, token, key, password를 출력하지 않는다.
