# 똘고리 판정

주의:
- 실행대상은 Claude Code나 Codex 중 정확히 하나로 쓴다.
- 실행대상을 택일하지 않은 열린 표현으로 쓰지 않는다.
- 작업은 설계/구축/검수/커밋 단계로 분리한다.
- 구현자와 최종 검수자는 다르게 배정한다.
- 커밋은 검수 통과 후 별도 Codex 수문장 단계로 진행한다.
- 지시문에는 secret/local/settings/API key/token/password/password_hash 값 출력 금지를 넣는다.
- 중단 조건에는 같은 오류 또는 같은 명령 실패 3회 반복, 범위이탈, 예상 외 dirty 혼입을 넣는다.
- 작업 후 정상 dirty 예상 상태를 명시한다. read-only 보고서 작성이 허용되는 경우에도 어떤 파일이 dirty로 남아야 정상인지 적는다.
- `git add .`, `git add -A`, 무단 commit/push 금지를 명시한다.
- 지시문 작성자는 최종 제출 전 `ai-harness/dev-team/SELF-FIX-LOOP.md`의 똘고리 지시문 생성 자가수정루프를 적용하고, 적용 결과를 지시문 하단에 아래 5개 중 하나로 짧게 남긴다.
  - 똘고리 통과: 실행 가능
  - 똘고리 보완 후 통과: 실행 가능
  - 똘고리 중단: 실행 금지, 이유 보고
  - 똘고리 SPEC 요구: 먼저 SPEC 작성 필요
  - 똘고리 범위분리 요구: 작업을 나눠야 함
