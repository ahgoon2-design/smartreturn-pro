# 파일 기반 루프 운영 규칙

이 폴더는 SmartReturn Pro 작업을 파일 기반 수동 루프로 돌리기 위한 것이다.
목적: 퍼나르기(복붙) 최소화 + 기록 영구 보존 + 순서 강제.
AGENTS.md와 충돌하면 AGENTS.md(보안·중단·언어)가 항상 우선한다.

## 1. 루프는 두 종류뿐
| 무엇을 돌리나 | 루프 이름 | 파란불 켜는 주체 | 언제 넘기나 |
|---|---|---|---|
| 지시문(스펙·구축·검수) | 똘고리 | Claude(작성자) | 파란불일 때 |
| 작업물(구축물·수정물) | 똘작이(작업물 루프) | 구축=빌더 자가 / 수정=검수자 재검수 | 파란불까지 |
- 똘고리 = 지시문 전용. 똘작이를 똘고리라 부르지 않는다.
- 똘작이 = 구축·수정 전용.

## 2. 빨간불 / 파란불
- 똘고리 파란불 = 판정 "통과" 또는 "보완 후 통과". 빨간불 = "중단/SPEC 요구/범위분리 요구".
- 작업물 파란불 = build 통과 + typecheck 통과 + 지시문 완료기준 충족.
  빨간불 = 하나라도 실패 → 고치고 재점검.
- 최대 3회 천장: green이면 즉시 종료. 3회 안에 green 못 만들면 멈추고 원인 보고(4회째 금지).
- 구축물 자가수정(빌더 자가 파란불)이 독립검수를 대체하지 않는다. 구현자≠검수자 유지.

## 3. 폴더 / 파일 규칙
- 작업 하나당 폴더 하나: ai-harness/loop/<TASK-ID>/ (예: SPEC-004, LOOP-012)
- 파일 루프 번호는 로컬 기록 순번이다. AGENTS.md의 5게이트(스펙 승인, 구현, 검증, 인수, 커밋 승인)를 대체하거나 재정의하지 않는다.
- 파일명: NN-<단계>.<상태>.md
  · NN = 일련번호(00,01,02...) → 순서 강제, 빠지면 보임
  · 단계 = goal / build-instruction / build-report / verify-instruction /
           verify-report / fix-report / commit
  · 상태 = BLUE 또는 RED (그 파일 생성 시점의 박제 판정)
- append-only: 기존 파일 덮어쓰기 금지. 빨간불→고침은 새 번호로 추가.
  (예: 04-verify-report.RED.md 다음 05-fix-report.BLUE.md 추가)

## 4. 필수 파일
- _index.md — 현황판. 지금 몇 단계, 빨간불/파란불, 다음 행동.
- 00-goal.md — ChatGPT 목표(짧게).
- 이후 01~ 단계 파일은 §3 규칙대로.

## 5. 요약 블록 규칙 (복붙 최소화 핵심)
- 모든 *보고서* 파일 맨 위에 5~8줄 [요약/판정] 블록을 둔다.
- 웹 도구(ChatGPT·Claude)에는 이 요약 블록만 복붙한다. 본문은 파일에만 둔다.
- Codex·클코는 저장소에서 본문을 직접 읽으므로 복붙하지 않는다.
- [요약/판정] 예시: 상태 🔵/🔴, 핵심 한두 줄, 다음 추천 단계.
- [요약/판정]은 보고 복붙을 줄이는 요약일 뿐이며, AGENTS.md·SELF-FIX-LOOP.md의 게이트와 중단 조건을 대체하지 않는다.

## 6. 사람 개입 = 파일 단계
- 게이트②(스펙 승인) = NNa-approval.md 또는 해당 파일에 [승인 ✅] 줄.
- 게이트⑤(커밋 승인) = NN-commit.md (해시 + stage한 파일 목록).
- 개입이 루프의 한 단계가 되므로 사람이 끼어도 루프 선상에 있다.

## 7. 커밋 / 아카이브
- 작업 폴더(SPEC-*/, LOOP-*/, _done/)는 .gitignore 대상. 커밋 안 함, 로컬 기록.
- 정식 산출물(SPEC, build/verify 보고서)은 평소대로 docs/specs·docs/reports에 게이트로 커밋.
- 이 README와 _template/은 추적/커밋한다.
- 커밋 끝난 작업 폴더는 ai-harness/loop/_done/<TASK-ID>/로 옮긴다.
